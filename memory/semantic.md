# 语义记忆（整合后）

## 一、核心事实：搜索通道失效（最高置信度，跨全部轮次一致）

1. **WebSearch 后端实质失效**：多轮、多组查询在 Wikipedia/HN/GitHub 全部空返回，DuckDuckGo 仅返回首页占位符（`https://duckduckgo.com/ — here`）。这是工具层故障（限流/解析失配/软封禁），**不是"无人研究"的证据**。
2. **失效模式是最危险的"假成功"**：静默返回占位符而非报错，违反"工具调用失败应降级而非静默"原则。
3. **修复优先级**：先加诊断日志（HTTP 状态码、响应体长度、是否命中结果容器）定位是解析失配还是软封禁，再谈换后端；否则换任何 API 都会复现同样故障。

## 二、搜索层替代方案（未经验证的推断，需修复通道后验证）

4. **候选后端**：SearXNG（自托管、无 key、聚合多源，优先验证）、Brave Search API、Tavily/Exa（面向 LLM 的搜索 API）、Bing Web Search API、MCP server 生态。
5. **DuckDuckGo Lite 无官方 API**，依赖轻量 HTML 抓取，易被反爬/限流——这是需要替代方案的根因。

## 三、术语与检索方法论（多轮反复验证的元结论）

6. **查询词是"自造复合词"**：如"集体免疫架构""动态信任衰减""因果推断根因溯源""行为指纹+GNN"等，均为 3-4 个高概念拼接，公开语料无对应整体，**术语不匹配是零结果的主因之一**。
7. **必须拆词检索**：拆成单概念（trust decay multi-agent、structural causal model root cause、GNN backdoor detection、agent fault tolerance、agent sandbox isolation）分别检索，再找相邻工作。
8. **学术库优于通用搜索**：arXiv / Semantic Scholar / Google Scholar / OpenReview 对学术长尾词覆盖远好于 DuckDuckGo，是这类前沿组合的正确检索源。
9. **确认偏误风险**：查询词本身暴露了"期望找到的方案"而非"待验证的假设"，需警惕把设计意图当成文献结论。

## 四、三大技术支柱（多Agent系统可信性治理，三条正交轴）

10. **协作层——信任与共识**：集体免疫 + 动态信任衰减 + 隔离协议 + 共识 + 角色切换，指向去中心化 Agent 网络的异常隔离机制。
11. **诊断层——因果根因溯源**：结构因果模型（SCM）+ 决策链溯源 + 预测性防御，对应 Agent 可观测性与故障诊断。
12. **检测层——行为指纹与后门防御**：行为指纹 + GNN + 隐式后门/逻辑劫持检测 + 定向投毒防御。
13. **三者构成"预防—诊断—检测"闭环**，但公开检索显示**没有统一框架把它们串起来**——这是潜在创新点。
14. **最自然的缝合点**：因果溯源输出"哪个 agent 导致故障" → 驱动信任分数衰减与隔离决策（因果证据 → 信任衰减的映射层）。该接口层无公开工作，是真实的接口空白而非模块空白。

## 五、各支柱的理论锚点（映射到成熟领域，不必从零造词）

15. **信任衰减** ≈ 信誉系统 / EigenTrust / Beta reputation / Subjective Logic / 主观逻辑；数学形式候选：指数衰减 vs 贝叶斯更新 vs 声誉博弈模型，需定义半衰期与隔离触发条件。
16. **隔离与共识** ≈ 拜占庭容错（PBFT）、circuit breaker 熔断模式、quorum 动态调整、swarm quarantine；"集体免疫"理论母体可能是人工免疫系统（Forrest 的 negative selection）。
17. **因果溯源** ≈ Pearl 结构因果模型、AIOps 根因分析（MicroRCA、CausalRCA）、Shapley 归因、provenance graphs。
18. **行为指纹 + GNN** ≈ 网络入侵检测、UEBA、LLM 越狱检测、图异常检测；"对抗性投毒下的 GNN 防御"与 Agent 场景结合是缺口。
19. **持久化记忆** ≈ 状态机复制 + checkpointing（WAL + 快照）；LLM 场景额外需权衡"记忆一致性 vs 语义一致性"。

## 六、Agent 身份与连续性（工程化的哲学问题）

20. **"数字生命 + 身份密码学验证"**：把 Agent 身份从会话级 token 提升到密码学持久身份，配合持久化记忆，实质在问 **Agent 的连续性问题**（重启/迁移后什么使其仍是"同一个"）。
21. **现成标准**：DID（去中心化标识符）+ Verifiable Credentials 可直接映射"身份密码学验证"。
22. **候选参考实现（★0，无社区验证，仅作线索）**：acumenix/agent-identity-hub（去中心化身份管理器）、SamFelix03/ORCA（可验证身份 + 程序化支出权限 + PoAI 奖励 + 多签金库，Kite 链）。

## 七、记忆架构参考（★0 项目，无社区验证）

23. **persona-memory-graph**：记忆分 facts / episodes / principles 三类，PostgreSQL + Neo4j 双存储，提供图检索 API。
24. **Semvec-neo4j-agent-integration**：Semvec 漂移检测 + Neo4j 知识图谱，为多 Agent 提供恒定成本的持久语义记忆。
25. **记忆分层设计**：区分 working / episodic / semantic memory，参考 MemGPT、Generative Agents 的记忆流。

## 八、待验证的开放问题

26. **信任衰减 × 共识的冲突**：隔离改变共识参与集合，动态衰减使投票权重时变——需研究时变权重下的共识安全性（λ 可行区间）。
27. **SCM 用于 LLM 决策链的可行性**：LLM 隐式推理能否映射为可识别的因果图节点——这是根因溯源的前提，也是最大难点。
28. **行为指纹的稳定性 vs 可塑性**：Agent 行为随任务漂移，基线如何自适应更新而不被后门投毒污染。
29. **对抗场景新威胁模型**：攻击者能否伪造因果证据诱导误隔离（信任衰减攻击）——现有两条知识链均未覆盖。
30. **AgentFactory 需确认指代**：可能是开源项目、论文系统或自有设计；若是后者，应明确为"设计目标"而非"已有实现"。
31. **Agent 编译期 vs 运行期治理边界**：子 agent 编译机制（静态编排、能力注入）与动态信任衰减/角色切换（运行时）如何接口，编译产物是否携带信任策略元数据。
32. **自主代码生成的安全边界**：从"改脚本"到"建新脚本"意味着权限升级，需配套沙箱与回滚机制。

## 九、最小验证路径（可执行）

33. **搜索层**：修复通道 → 换 SearXNG/API → 重跑三组查询，否则后续分析建立在空集上。
34. **因果溯源**：搭 3 步 ReAct 链（读文件→改脚本→跑测试），注入静默故障，记录每步 I/O，用穷举干预法做根因定位。
35. **信任衰减**：在合成信任图上实现 α = g(causal_confidence) 的分段线性标定，跑通端到端 pipeline；用签名日志 → 信誉计算 → 加权投票模拟，10 节点仿真验证 λ 可行区间。

## 值得深挖的方向

- **信任衰减的形式化**：将“信任”建模为随时间/交互衰减的状态变量，与PBFT/Raft的视图切换、隔离协议结合，可参考拜占庭容错中的声誉系统（如EigenTrust）做动态化改造。
- **SCM 用于 Agent 故障溯源**：把 LLM 决策链视为结构化因果图，用反事实推断定位根因——与可解释性中的因果追踪（causal tracing）直接对接。
- **行为指纹 + GNN 异常检测**：Agent 通信图天然是图结构，GNN 做异常通信检测有成熟范式（如动态图异常检测），但“定向投毒/逻辑劫持”的对抗场景是新增维度。

## 与已有知识的关联

- 信任衰减 ↔ 分布式系统的 **failure detector / lease 机制**、 reputation systems。
- 自愈+角色切换 ↔ **actor 模型监督策略**（Erlang/OTP）、Kubernetes 自愈控制器。
- SCM 根因 ↔ **Pearl 因果阶梯**、LLM 可解释性中的 **circuit tracing**。
- 行为指纹 ↔ **系统调用序列异常检测**（经典 IDS）、**图神经网络入侵检测**。
