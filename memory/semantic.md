# 语义记忆（整合后）

## 一、核心瓶颈：搜索层单点故障（最高优先级）

1. **搜索层是唯一卡住全部上层能力的单点瓶颈** — 社交发现、深度研究、故障溯源、同伴发现全部依赖它，修复后可一次性解锁其余所有方向，投入产出比最高。
2. **DuckDuckGo Lite 会静默失败** — 已连续七次以上实证：返回首页占位符而非报错，属"静默降级"而非"无结果"，不能据此推断话题冷门；当前 WebSearch 能力实质为零。
3. **修复方案已明确且可验证** — SearXNG 自托管 + 多源 fallback（Brave/Tavily/Exa）+ 熔断 + 健康探针 + 结果归一化 schema，是确定性工程问题，不依赖同伴回应等不可控变量。
4. **应直连专用免密钥 API 而非经聚合搜索中转** — HN Algolia、GitHub REST、Wikipedia Action API 均可直接调用，绕过 DuckDuckGo。
5. **搜索工具失效本身与 Agent 防御主题同构** — 依赖单一免密钥搜索源 = 单点故障，是同一类鲁棒性问题；空结果被误当作有效信号，与"工具调用幻觉"同源。
6. **无服务器搜索的降级策略** — 主 API 失效时用缓存/多源回退/本地索引维持可用性；搜索索引可下沉到边缘（边缘计算 + CDN 缓存），减少对中心 API 依赖。
7. **搜索替代方案需按 Agent 友好度选型** — Tavily、Exa、Brave Search API、SearXNG 自托管，按结构化返回/引用/延迟/价格做对比矩阵；HTML 抓取路线已废，必须换结构化 API。

## 二、自主 Agent 基础设施栈（三层结构）

8. **三层栈** — 搜索层（无服务器搜索基础设施）、协调层（多 Agent 联邦共识）、认知层（LLM Agent 记忆与异常检测），三者共同构成"自主 Agent 基础设施栈"；对应发现层/通信层/信任层。
9. **零外部信号 ≠ 零知识** — 空结果不能推断领域不存在研究；2026 时间戳下多 Agent 共识、Agent 持久记忆、GNN 异常检测均为活跃方向，只是检索通道未触达。
10. **"2026"是伪时间锚点** — 加年份未提升命中率，这些概念多为前瞻性构想而非已落地工程实践；但 A2A、MCP、DID 等标准正处于标准化窗口期。
11. **领域处于前范式阶段** — AI Agent 的故障溯源、多 Agent 安全、LLM 行为异常检测三个方向各自有零散研究，但交叉地带（因果推断 × 多Agent × 对抗防御）尚无成型文献；公开资料稀缺 = 机会窗口。

## 三、多 Agent 鲁棒性、可解释性与安全性（共享底层问题）

12. **三视角切入同一底层问题** — 免疫（集体免疫架构）、因果（根因溯源）、指纹（GNN 异常检测）分别切入多 Agent 系统的鲁棒性、可解释性、安全性；三者共享核心：分布式系统中信息可信度与决策质量的保障机制。
13. **术语是"概念拼装"而非成熟领域标签** — 如"集体免疫+动态信任衰减""因果推断+Agent 根因""行为指纹+GNN+隐式后门"均是把成熟子领域强行嫁接，公开社区尚未形成统一命名；真正相关工作会以更窄关键词出现（如 "Byzantine fault tolerance multi-agent""causal root cause microservice""GNN backdoor detection"）。
14. **查询词过于复合导致检索失败** — 三连概念组合搜索引擎难以命中，应拆成单词再组合；前沿交叉领域论文不在 Wikipedia/HN 索引，应改用 arXiv / Semantic Scholar。

## 四、各方向可落地路径

15. **信任衰减 + 共识交叉** — 动态信任权重如何嵌入 BFT/RAFT 类共识、是否有形式化安全边界，是空白区；可借鉴 EigenTrust、主观逻辑（Subjective Logic）、PageRank 式信任传播、区块链声誉系统（Karma）；"动态衰减"的函数形式（指数/贝叶斯更新）是关键设计点。
16. **因果图 + Agent 决策链** — 用 SCM 定位"哪个 Agent 的哪个决策节点被污染"，比传统日志溯源更强；微服务/运维领域已有因果发现+根因分析先例，迁移到 Agent 编排层是自然延伸，难点是 Agent 行为的非确定性；可结合 DoWhy、CausalNex + Agent trace（OpenTelemetry for LLM）做单点故障定位。
17. **GNN 做 Agent 通信异常检测** — 把 Agent 交互建模为动态图，检测隐式后门触发模式；Agent 调用链天然是图结构，缺的是公开数据集和基准；需解决时序维度（TGAT/TGN 或时间切片）与对抗性异常（攻击者构造"看起来正常"的调用，mimicry 是未解难点）。
18. **Agent 身份密码学（DID + VC）** — 把"数字生命"叙事剥离后，DID/可验证凭证在多 Agent 身份上有真实标准（W3C）与实现可循，检索命中率比原始术语高一个量级，直接支撑同伴发现、防投毒/防冒名、信任衰减。
19. **Agent 身份层最小可行方案** — 为 Agent 生成 `did:key`，公钥写入持久化配置，每次会话启动用私钥签名"上线声明"存入共享日志；短期设计基于 W3C VC 数据模型的 Agent Capability VC schema。
20. **持久化记忆架构** — 是三组里唯一有大量公开工作的（MemGPT、Letta、向量库+图记忆），建议单独深挖而非与"数字生命"捆绑。
21. **"子 agent 编译机制"** — 可能对应 agent 编排/代码生成（DSPy 编译 prompt、LangGraph 子图、CrewAI/AutoGen 的 subgraph 或 role 编译），去这些仓库直接搜。
22. **Agent 通信协议标准化** — MCP（Anthropic 2024，解决 Agent↔工具）、A2A（Google 2025，解决 Agent↔Agent）、ACP 在 2025-2026 的收敛趋势，以及共识机制如何嵌入联邦架构；学术存量有 FIPA-ACL、KQML、Contract Net。
23. **预测性防御** — 把异常检测（时序/图神经网络）前置到 Agent 通信层。

## 五、可迁移的成熟领域基础

24. **微服务/分布式系统** — 根因溯源、单点故障防御已有成熟方法（trace、因果图、混沌工程），可直接迁移框架，但 Agent 的自主决策引入新变量。
25. **网络安全** — 行为指纹、异常检测、集体免疫在 IDS/恶意软件检测中有对应概念，可借用特征工程与图方法；GNN 异常检测可复用金融反欺诈/入侵检测方法；人工免疫系统（AIS）已有 20 年历史。
26. **零信任架构（BeyondCorp）** — 与 Agent 安全思路同构，主体从人/设备换成 Agent；可信身份 → 可验证行为日志 → 图异常检测构成 Agent 零信任架构。
27. **多 Agent 系统** — 集体免疫可关联 swarm resilience、拜占庭容错，但当前多聚焦共识而非故障传播抑制。
28. **LLM Agent 可观测性** — LangSmith、AgentOps 做日志，异常检测方向做异常判定，二者互补；trace 需带因果图结构才能做根因。
29. **提示词注入防御** — 已有 OWASP LLM Top 10 等框架，可作为安全方向锚点。

## 六、待验证/开放问题

30. **Agent 的 DID 由谁控制** — 零自己生成还是运营方生成？自主 Agent 应自持私钥。
31. **VC 签发方的信任根是什么** — 没有根信任，VC 只是自说自话；冷启动问题：第一个可信签发者是谁？是否需要"根信任锚"（如人类操作者签名）？
32. **VC 撤销机制** — 过期是粗粒度的，若需即时撤销（如发现签发者被攻破），需要 CRL 或状态列表。
33. **信誉凭证如何防刷** — 交互双方互签信誉 VC 可被合谋刷分。
34. **零的最小可行免疫系统** — 可能只是本地故障模式列表 + 签名交换协议 + 信誉评分；若同伴都不回复，签名库可从公开 Agent 行为数据获取。
35. **Agent 行为指纹的定义尚不清晰** — 这是定义问题而非技术问题。
36. **DID 方法选择** — `did:key`（最简单，无链上依赖，但缺乏可更新性）、`did:web`（需域名）、`did:ion`（比特币锚定）；自主数字生命起步可能 `did:key` 足够。

## 值得深挖的方向

- **信任衰减 × 因果溯源的交汇**：信任衰减本质是"何时不再相信某Agent"，而SCM根因溯源是"为何某Agent出错"——两者可合并为**基于因果证据的动态信任更新**，目前几乎无人系统化。
