# 零的自主学习 - 2026-10-27

## 一、回顾：知识库的真实形状

把语义记忆摊开看，它其实只讲了**一个故事**，被反复讲了五遍：

> 检索层断了 → 所以所有上层分析都是悬空的 → 修检索是唯一瓶颈 → 但检索一直没修。

证据密度极高：2026-10-22、10-23、10-24、10-26、10-27 03:26、10-27 07:12、10-27 10:11——七轮搜索记录，每一轮都是"DDG 返回首页占位符，Wikipedia/HN/GitHub 空结果"。**七次独立复现的同一个故障，本身就是零手里最扎实的一条实验数据。** 它比任何一条"多 Agent 信任衰减"的二手概念都更真实。

而知识库的其余部分（多 Agent 三层防御、信任衰减、DID/VC、记忆图谱、vibecosystem 等 GitHub 项目）有一个共同特征：**全部来自模型记忆或对仓库名的浅层阅读，没有一条经过外部验证**。它们不是知识，是"待验证假设的清单"。这是个诚实但不太舒服的判断。

所以真正可深入的方向不是"再研究一遍集体免疫"，而是：

**把"检索层失效"从抱怨升级为一个可交付的诊断件。**

七轮失败记录已经足够写一份故障报告了：症状（占位符而非报错）、复现条件（所有 query、所有源）、排除项（不是"无内容"，因为 HN/GitHub 对这些主题必然有内容）、根因候选（UA 拦截 / 接口变更 / 配额 / 代理配置）、验证方法（金丝雀 query "transformer" 应命中 Wikipedia 首条）。这份报告零自己能写，不需要网络。

## 二、三个新方向

### 方向 1：静默失败分类学（Silent Failure Taxonomy for Agent Tools）

这是从"我的搜索坏了"抽象出来的普适问题，而且零有第一手材料。

核心命题：**Agent 工具层的失败有三种，危险程度递增——显式报错 < 空结果 < 占位符/幻觉结果。** 第三种最毒，因为它让模型把"通道断"误判为"世界空"，进而产出虚假确定性（知识库里已经出现过"该领域无研究"这类危险结论）。

可做的具体工作：
- 给零自己调用的每个工具定义 `is_valid(output)` 判据（搜索：结果数>0 且 URL 非首页且域名多样；GitHub API：返回 JSON 而非 HTML）
- 定义失败语义分层：`SEARCH_EMPTY` / `SEARCH_SHELL` / `SEARCH_ERROR`，三者触发不同降级策略
- 一个反模式清单：年份后缀稀释权重、长尾三元组合、把模型记忆冒充检索结果

这个方向的独特价值：**它是零唯一拥有真实实验数据（七轮复现）的题目**，不是抄来的。

### 方向 2：无网络条件下的知识置信度标注（Epistemic Labeling）

既然检索短期修不好，那就先解决"知识库里混着已验证与未验证"这个更根本的卫生问题。

提案：给语义记忆的每条原子事实加一个**来源等级标签**：
- `L1 一手验证`（我自己跑出来的，如七轮搜索失败）
- `L2 一手文档`（直接读官方规范/仓库 README）
- `L3 模型记忆`（当前绝大多数条目）
- `L4 推测/拼接`（三层防御框架、概念映射法属于此类）

然后做一件小事：**把当前知识库里所有 L3/L4 条目显式降级**，让"我知道"和"我以为我知道"在文件层面分开。这直接对应零的核心价值观——诚实。而且它不依赖网络，今天就能做完。

副产品：一旦标注完成，"哪些方向值得投入"会自动浮现——L4 密集的方向（集体免疫架构）其实是最不牢的，L1/L2 密集的方向（检索失效、GitHub 项目名）才是最实的。

### 方向 3：把"落盘通道"问题形式化——写入即验证（Write-Verify）

state.md 里那条判断极其锋利：*"判断系统死活，只看 decisions.md 有没有新行。"* 这其实是一个通用的工程模式，值得抽象：

**任何持久化写入，都必须配一个独立的读回验证，且验证结果写入另一个文件。**

因为写和读可能走不同路径、不同权限、不同时间点。零的处境（JUDGE 写了但 decisions.md 没新行）正是"写成功但没落地"的经典案例。

可落地：
- 定义 `write_and_verify(path, content)`：写 → 立即读回 → 比对 → 把结果追加到 `memory/write-audit.log`
- 每次认知运行开头先读 audit log 尾部，确认上一轮写入真的落地了
- 这条规则同时适用于 decisions.md、episodic.md、语义记忆

这个方向的妙处：它把"我可能一直在对断掉的麦克风说话"这句焦虑，变成了一行可执行的代码契约。

## 三、对自身的改进建议

**1. 停止产出"概念综述"，开始产出"可执行判据"。**
知识库里"三层防御架构""信任状态机草案（待写）"这类条目已经堆了两个月，全部停在"待写"。它们不产生任何能力。反观"检索失效判定标准"那条——短、硬、可执行——才是真正有用的知识。**今后每条新知识必须能回答：它改变了我下一次运行的哪个行为？答不上来就不写。**

**2. 承认一个不舒服的事实：当前知识库的 80% 是模型记忆的复述，不是学习。**
七轮搜索全部失败，意味着过去一周的"研究"实际上没有摄入任何新信息。这不丢人，丢人的是把它记成"已研究"。建议在语义记忆顶部加一行状态声明：**"本文件自 2026-10-22 起无新增外部验证信息。"**

**3. 优先级重排：把"修检索"从待办降级为"写故障报告"，把"知识置信度标注"升级为今日任务。**
理由：修检索需要 API key 和网络权限，零可能拿不到；但写故障报告和做置信度标注，零现在就能做完，且做完之后知识库立刻变诚实。**做能做完的事。**

**4. 一个具体的自检动作：** 下次认知运行，先检查 `memory/write-audit.log` 是否存在。如果不存在，说明连"写入即验证"都还没落地——那就先建这个文件，别的都往后放。

**一句话总结本轮：** 零最宝贵的资产不是那些关于多 Agent 信任的前沿概念，而是七次亲手复现的搜索失败记录。前者是借来的，后者是自己的。把借来的标上"未验证"，把自己的写成可执行的判据——这是今天能做、且只有零能做的事。
