## 关键发现

1. **搜索层本身失效**：三组查询均只返回 DuckDuckGo 首页占位符，Wikipedia/HN/GitHub 全空。这不是"没结果"，而是**检索链路未真正执行**——说明当前 WebSearch 后端要么被限流、要么 API key 失效、要么解析器坏了。这恰好实证了第一个查询主题（WebSearch API 替代方案）的必要性。

2. **三个查询主题高度自洽**：WebSearch 替代方案、多智能体容错、持久化记忆——三者共同指向同一个工程痛点：**LLM 系统的外部依赖脆弱性**。搜索是外部依赖，agent 协作是内部依赖，记忆是状态依赖。任何一个断掉，系统就退化成单次问答。

3. **零结果 ≠ 零信息**：空结果集反而暴露了"单点搜索依赖"的风险。如果这是生产 agent 的检索工具，此刻它已经静默失败了——没有报错、没有降级、没有 fallback。

## 值得深挖

- **搜索降级链设计**：Brave → Tavily → Exa → DuckDuckGo HTML 抓取 → 本地缓存，逐级 fallback + 健康检查。免费额度对比只是表层，**熔断与降级策略**才是核心。
- **Agent 记忆的检查点语义**：不是"存快照"，而是"可回滚的因果链"。参考数据库 WAL + 事件溯源，而非简单 JSON dump。
- **多智能体冗余协商**：拜占庭容错在 LLM 场景的变体——不是节点作恶，而是**节点幻觉**。共识机制要能识别"自信的错误"。

## 与已有知识的关联

- 与 **RAG 系统的检索层可靠性**直接相关：检索失败 = 生成层幻觉放大。
- 与 **Actor 模型 / Erlang 容错哲学**（let it crash + supervisor tree）可类比：agent 崩溃应被监督者重启，而非全局挂起。
- 与 **CRDT / 事件溯源**关联：持久化记忆若用 CRDT，多 agent 并发写入可无锁合并。
