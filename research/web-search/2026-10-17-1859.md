## 关键发现

1. **搜索结果全部为空壳**：三次搜索均只返回 DuckDuckGo 首页链接，Wikipedia/HN/GitHub 零结果。这不是"没有相关信息"，而是搜索管道本身失效——DuckDuckGo Lite 的 HTML 结构变更或反爬策略导致解析器抓不到结果条目。**当前 WebSearch 方案不可用，需先修复或替换。**

2. **三个查询主题高度相关**：云端搜索 API 替代方案、多 Agent 通信协议、Agent 持久化记忆+身份验证——这实际上是同一个系统设计问题的三个切面：一个需要可靠外部信息获取、多角色协作、可验证身份与记忆的 Agent 架构。

## 值得深挖的方向

- **搜索后端替换优先级最高**：Brave Search API、SearXNG 自建、Tavily/Exa（面向 LLM 的搜索 API）是 2026 年主流替代路线，需对比延迟、成本、结构化输出质量。
- **Agent 通信协议**：MCP（Model Context Protocol）已成事实标准之一，A2A（Agent-to-Agent）协议、FIPA-ACL 传统方案值得对照；共识算法在 Agent 场景更多是"投票/仲裁"而非 BFT。
- **身份密码学验证**：DID（去中心化标识符）+ Verifiable Credentials 是 Agent 身份的主流思路；记忆持久化则涉及向量库 + 事件溯源 + 签名日志。

## 与已有知识的关联

- 搜索管道失效 → 与你之前对"工具层可靠性"的关注一致：**任何 Agent 系统的瓶颈常在工具层而非推理层**。
- 多 Agent 共识 + 密码学身份 → 呼应"零信任架构"思路：Agent 间不应默认信任，需签名验证每条消息来源。
- 持久化记忆 + 身份验证结合 → 记忆条目应带签名与时间戳，防止记忆投毒（memory poisoning），这是 2026 年 Agent 安全的核心议题。

**建议**：先修搜索层（换 API 或修解析器），否则后续所有调研都是盲搜。
