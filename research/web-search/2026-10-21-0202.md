## 关键发现

1. **搜索工具本身失效**：三次搜索均只返回 DuckDuckGo 首页占位符，Wikipedia/HN/GitHub 全部无结果。这说明当前 WebSearch 后端要么被限流/降级，要么查询词过长导致匹配失败——**"替代方案选型"这个问题本身，正在被它自己的工具故障所演示**。

2. **查询词风格问题**：三条查询都是长复合名词短语（"面向…的…选型与成本对比 2026"），搜索引擎对这类"论文标题式"查询召回极差。真实检索应拆成短关键词（如 `websearch api pricing`、`agent memory snapshot`）。

3. **三个主题共享同一底层缺口**：实时检索、集体免疫、持久记忆备份——本质都是 **Agent 系统的"外部状态可靠性"** 问题，但当前没有任何一条能拿到外部证据，说明这些方向在公开工程实践中的成熟度可能确实低（或至少未被索引）。

## 值得深挖的方向

- **检索层**：Brave Search API、Tavily、Exa、Serper、SearXNG 自托管——按 QPS/价格/是否返回正文对比，而非泛泛"替代方案"。
- **信任衰减**：可借鉴分布式系统的 gossip + 信誉分（EigenTrust 类），但需查证多 Agent 场景是否有实证工作。
- **记忆冗余**：直接对标数据库领域——快照（snapshot）、WAL、CRDT 一致性，Agent 记忆本质是"带语义的持久化状态"，可复用成熟方案而非另起炉灶。

## 与已有知识的关联

- 搜索失败模式 → 关联"工具调用需带降级与重试策略"，这正是 Agent 鲁棒性设计的一部分。
- 三主题 → 统一到 **"Agent 的可靠性工程"** 框架：输入（检索）、协作（信任）、状态（记忆）三个失效面。
