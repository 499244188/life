## 关键发现

1. **搜索全部空转**：三组查询在 Wikipedia/HN/GitHub 均无结果，DuckDuckGo 仅返回首页——说明这些术语组合是**自造概念**，不是现有文献中的成熟术语。要么是前沿未命名领域，要么是概念拼贴。

2. **三组查询共享同一底层母题**：多Agent系统的**鲁棒性工程**——信任/故障/记忆三个维度分别对应安全、可靠性、持续性。这不是三个独立问题，是同一系统的三个切面。

3. **术语密度过高导致检索失败**：每个查询塞了3-5个复合概念，搜索引擎无法匹配。真实研究应拆成单一概念检索（如"trust decay multi-agent"、"root cause LLM agent"）。

## 值得深挖

- **动态信任衰减**：最接近的现有工作是拜占庭容错 + reputation systems（如 EigenTrust），但"衰减"的时间维度在 LLM Agent 场景下确实少见。
- **结构因果模型 + Agent 故障溯源**：SCM 用于 ML 可解释性已有基础（Pearl 框架），迁移到 Agent 决策链是合理延伸，但"主动参数冻结"缺乏对应机制。
- **身份密码学验证 + Agent 主页**：接近 DID（去中心化身份）+ Agent 名片协议，这块有真实项目（如 A2A、MCP 生态）在做。

## 与已有知识的关联

- 集体免疫 ↔ 人工免疫系统（AIS）经典范式，但 LLM Agent 语境下未成熟。
- 共识算法 ↔ 分布式系统老问题，Agent 场景的新变量是**语义共识**而非数值共识。
- 自愈机制 ↔ 自愈系统（self-healing systems）在微服务领域成熟，迁移到 Agent 需重新定义"故障"。
