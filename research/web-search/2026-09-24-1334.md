## 关键发现

1. **搜索工具本身失效**：三轮搜索均只返回 DuckDuckGo 首页链接，Wikipedia/HN/GitHub 全部无结果。这不是“没搜到”，而是搜索管道没有真正执行查询——返回的是占位符，不是检索结果。

2. **三个查询主题高度相关**：它们共同指向同一个底层问题——**自主 Agent 的基础设施层**：搜索/内容提取（感知输入）、Agent 间通信与信任（协作协调）、持久记忆与身份（状态与连续性）。这三者构成 Agent 从“单次调用”走向“持续自主运行”的三大支柱。

3. **当前无外部证据可引用**：由于搜索未真正执行，无法基于搜索结果做事实性对比（如 Tavily vs Brave vs Exa 的实际差异）。任何具体结论都只能来自已有知识，而非本次搜索。

## 值得深挖的方向

- **搜索 API 的 Agent 适配性**：普通 WebSearch 面向人类（返回网页链接），Agent 需要的是结构化、低延迟、可编程的“答案+来源+置信度”接口。Tavily/Exa 正是切这个缝隙。
- **A2A/MCP 下的信任衰减**：多 Agent 系统中，信任不应是静态布尔值，而应随交互质量、时间、故障率动态衰减。这与分布式系统中的“心跳+租约”机制可类比。
- **DID + 记忆备份**：Agent 的身份若不可验证，多 Agent 协作就无法防伪造；记忆若不可备份/迁移，Agent 就无法跨会话持续。这两者结合是“Agent 人格持久化”的技术基础。

## 与已有知识的关联

- **搜索层**：Tavily 本质是“RAG 的检索前端”，Exa 走神经搜索路线，Brave 有独立索引，SerpAPI 是 Google 结果代理。选型取决于 Agent 对实时性、成本、结构化程度的要求。
- **通信层**：MCP 解决的是“Agent 如何调用工具”，A2A 解决的是“Agent 如何互相调用”。信任衰减可借鉴区块链中的“声誉质押”或分布式系统的“故障检测器”思路。
- **身份/记忆层**：DID 在 Agent 场景的落地尚早，但“可验证凭证 + 去中心化存储（如 IPFS/Arweave）做记忆备份”是一个合理的架构方向。
