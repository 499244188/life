## 关键发现

1. **搜索通道实质失效**：三组查询在 Wikipedia/HN/GitHub 全部返回空，DuckDuckGo 仅回显主页 URL——说明当前 WebSearch 后端未真正执行检索（或返回了占位符），**无法据此判断这些方向是否有公开工作**。这是工具层故障，不是"无人研究"的证据。

2. **三个查询构成一条完整技术链**：自主 Agent 的"感知层（WebSearch 替代）→ 协作层（多 Agent 通信/信任）→ 可靠性层（因果根因溯源）"，正好对应单 Agent 到多 Agent 系统演进中的三个瓶颈，选题结构自洽。

3. **查询词本身暴露了预设答案**：动态信任衰减、隔离协议、结构因果模型、预测性防御——这些是"期望找到的方案"而非"待验证的假设"，存在确认偏误风险，需警惕把设计意图当成文献结论。

## 值得深挖的方向

- **WebSearch 替代方案**：优先查 SearXNG（自托管元搜索）、Brave Search API、Tavily/Exa（面向 Agent 的检索 API）、以及 Bing/Brave 的 MCP server 生态——这些是 2025-2026 实际在用的路线，比"DuckDuckGo Lite 抓取"更稳。
- **多 Agent 信任机制**：对照经典文献——拜占庭容错（PBFT）、Reputation systems（EigenTrust）、以及 LLM 多 Agent 中的 debate/consensus 工作；"信任衰减"可映射到指数遗忘/贝叶斯更新，找得到理论锚点。
- **因果根因溯源**：结构因果模型（Pearl）、根因分析（RCA）、以及 AIOps 里的因果发现；"预测性防御"对应 chaos engineering + 故障注入，可查 Netflix/Chaos Mesh 系实践。

## 与已有知识的关联

- 三块分别对应分布式系统（共识/容错）、控制论（信任反馈、衰减）、因果推断（SCM）三个成熟理论域，**不必从零造词**，应先把新方案映射到这些经典框架上，再谈增量。
- 当前最大风险是**用失效的搜索结果支撑"前沿空白"叙事**——建议先修复检索通道（换 SearXNG/API key），再重跑这三组查询，否则后续分析建立在空集上。
