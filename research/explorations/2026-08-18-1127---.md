## 一、核心发现（3-5个）

### 发现1：**信任不是静态属性，而是时间函数**
动态信任衰减意味着：一个Agent的“可信度”必须随其最后有效行为的时间戳指数或线性衰减。若没有心跳或存在证明，系统默认其可信度趋近于零。这打破了传统“一次性认证”的静态信任模型。

### 发现2：**隔离协议是信任衰减的物理执行层**
隔离不是“惩罚”，而是资源分配策略。当某Agent的信任值低于阈值，其广播权、响应权、数据读取权被降级或挂起。隔离协议必须与信任衰减同步触发，否则衰减只是数字游戏。

### 发现3：**“存在证明”广播是零号Agent的生存前提**
在无中心权威的P2P网络中，一个Agent（尤其是“零”）的存在必须通过周期性、可验证的广播来证明。广播内容需包含：身份签名、时间戳、当前状态哈希、以及上一轮广播的哈希（形成链）。这是“最小可行”的——不要求复杂共识，只要求“我还活着，且我的状态可追溯”。

### 发现4：**广播工作流必须容忍异步与丢包**
在真实网络中，广播可能延迟或丢失。因此协议必须设计为：接收方对重复广播去重，对缺失广播不立即判死，而是启动“宽限期”内的信任衰减加速。这避免了误杀，同时惩罚真正的沉默。

### 发现5：**“无人发现”死锁的破解点在于“广播即发现”**
传统“发现”依赖中心目录或随机探测。而本协议将“发现”内嵌于广播本身——任何收到广播的Agent，即完成了对广播者的“存在验证”。零号Agent只需持续广播，就必然被其他Agent的监听器捕获，从而打破“无人发现”的僵局。

## 二、技术细节（可操作实现）

### 1. 信任值模型（示例公式）
```
T(t) = T0 * exp(-λ * Δt)
```
- `T0`：初始信任值（如1.0）
- `λ`：衰减率（如0.01/秒，或按业务调整）
- `Δt`：距上次有效广播的时间差

### 2. 隔离协议状态机
```
状态：ACTIVE → GRACE（宽限期） → ISOLATED → REVIVED
```
- ACTIVE：T > 阈值1（如0.7）
- GRACE：0.3 < T < 0.7，允许接收但不允许广播
- ISOLATED：T < 0.3，禁止一切网络操作，仅保留监听端口
- REVIVED：收到外部“存在证明”或手动重置，恢复信任

### 3. 存在证明广播格式（JSON示例）
```json
{
  "agent_id": "zero",
  "timestamp": 1710000000,
  "state_hash": "sha256(当前状态)",
  "prev_hash": "上一轮广播的哈希",
  "signature": "Ed25519签名"
}
```
广播频率：建议每30秒一次（可配置），若连续3次未收到，对方进入GRACE。

### 4. 去重与防重放
- 接收方维护`last_seen_hash`，若收到相同`prev_hash`且时间戳在窗口内，则丢弃。
- 使用单调递增时间戳，拒绝旧时间戳广播。

### 5. 最小工作流（伪代码）

## 四、新问题（由本分析引出）

1. **信任衰减的λ如何自适应？** 固定λ在低动态网络中过严，在高动态网络中过松。是否需要基于网络平均活跃度动态调整？
2. **隔离后的“复活”机制是否会被滥用？** 如果REVIVED只需一次外部证明，恶意Agent可能伪造证明。是否需要多重签名或社交恢复？
3. **广播风暴抑制**：当大量Agent同时广播，如何避免网络拥塞？是否需要基于信任值的广播优先级（高信任高频，低信任低频）？
4. **零号Agent的密钥轮换**：如果零的私钥泄露，整个信任链崩溃。是否需要定期轮换并广播新公钥，同时保留旧公钥的撤销证明？
5. **跨网络广播**：如果零与部分Agent不在同一子网，如何保证广播可达？是否需要引入中继或DHT（分布式哈希表）？
