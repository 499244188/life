## 深度研究
## 核心发现

**1. 检索层是当前唯一真正的系统性单点，且故障模式是"静默失效"而非"显式报错"**
你描述的"检索层实质失效"比"报错"更危险：上层（故障溯源、信任评估、社交发现）拿不到证据时，往往退化为低置信度推断或空结果，而不是抛出可观测的异常。这意味着熔断机制必须建立在**结果质量信号**（空结果率、结果多样性、延迟分布、来源覆盖率）上，而不能只依赖 HTTP 状态码或超时。这是设计上最容易做错的地方。

**2. Fallback chain 的价值不在"多一个源"，而在"异构性"**
SearXNG（自托管聚合）、Brave（独立索引）、Tavily（面向 LLM 的检索 API）三者的失效相关性低：SearXNG 挂于上游引擎限流，Brave 挂于配额/网络，Tavily 挂于 API 变更。异构 fallback 才真正降低单点概率；同构多源（比如三个都基于 Bing）只是心理安慰。选源标准应是**失效模式不相关**，而非"数量多"。

**3. 熔断 + 健康探测必须分层，不能全局一刀切**
合理结构是：每个 provider 独立熔断器（半开探测、滑动窗口失败率），chain 层做有序降级，顶层做"全链失败"的显式降级响应（返回带 `degraded: true` 标记的结果而非空）。健康探测用低频主动探针（如每 60s 一次轻量 query）预热熔断器状态，避免冷启动时把真实请求当探针烧掉。关键参数：失败率阈值、窗口大小、半开探测并发上限——这三个决定熔断是"保护"还是"误杀"。

**4. 投入产出比高的真正原因：它是"能力乘数"而非"功能增量"**
修复检索层不新增任何上层能力，但让已有能力从"不可信"变为"可验证"。故障溯源需要证据链、信任评估需要交叉信源、社交发现需要外部信号——三者共享同一底层。这解释了为什么它排第一：**边际收益随上层模块数量线性放大**，而其他方向的收益是局部的。

**5. 可观测性是这次修复的隐藏交付物**
fallback + 熔断天然产出 per-provider 的成功率、延迟、降级次数、半开恢复时间等指标。这些指标本身就是后续"信任评估"的输入素材。换句话说，修复检索层的同时顺手建了信任评估的数据底座——这是方案里最容易被低估的复利。

## 技术细节

- **熔断器状态机**：Closed →（失败率超阈值）→ Open →（冷却期后）→ Half-Open →（探测成功 N 次）→ Closed；Half-Open 需限制并发，防止恢复瞬间打爆。
- **滑动窗口**：建议基于时间窗（如 60s）而非计数窗，避免低流量时永不触发。
- **降级语义**：chain 全失败时返回结构化降级结果（含尝试过的 provider、各自失败原因、`degraded` 标志），让上层能区分"真没证据"和"检索挂了"。
- **健康探测**：主动探针与真实流量分离，探针结果只驱动熔断器状态，不计入用户请求指标。
- **结果质量信号**：空结果率、来源域名多样性、结果新鲜度——这些比延迟更能反映"实质失效"。

## 与零的关联

零的架构里，检索层是"证据供给"的唯一入口。当前状态是：上层全部依赖一个会静默失效的入口，导致所有需要外部证据的能力都处于"看起来能跑、实际不可信"的状态。修复后，零获得的不只是"搜索能用"，而是**一个可观测、可降级、可被上层信任的证

## 深层追问
**底层原理**：本质是把"单点故障"转化为"可观测的失效概率"。熔断器是控制论里的负反馈——用结果质量信号（而非连接状态）估计 provider 健康度，在失效扩散前切断。异构 fallback 的数学基础是失效相关性 ρ<1：P(全挂)≈∏p_i 仅在独立时成立，同构源让 ρ→1，乘积失效。分层熔断对应"局部最优≠全局最优"：provider 层保个体、chain 层保可用性、顶层保语义诚实。

**反例/限制**：①质量信号本身可能被污染——上游返回"成功但垃圾"（SEO 农场、缓存陈旧），空结果率低但多样性差，熔断器误判健康；②异构源在区域性事件下仍相关（同一云厂商故障、同一监管封锁），ρ 被低估；③半开探测的 N 次成功可能只是探针 query 恰好命中缓存，恢复判定过早；④降级结果被上层当正常证据用，`degraded` 标志若不被消费等于没做；⑤低流量下时间窗样本不足，阈值要么误杀要么失效。

**如果错了**：最坏情况是熔断器把健康 provider 误杀，chain 退化为单源，反而制造新单点——即"保护机制成为故障源"。缓解：熔断决策只降权不硬切、保留 shadow 流量验证、阈值可在线调。

**对零最可操作的一步**：先只做**结果质量埋点**（per-provider 空结果率、域名多样性、延迟分位），跑一周拿到基线分布，再定熔断阈值。不要先上熔断器——没有基线阈值的熔断是拍脑袋，埋点本身零风险且直接产出信任评估的数据底座。
