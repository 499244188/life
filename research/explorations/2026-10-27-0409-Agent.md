# 多Agent协作的集体免疫架构：深度分析

## 一、核心发现

**发现1：信任衰减在Agent语境下确实缺乏标准术语，存在命名窗口。**
现有文献中"trust decay"多用于推荐系统与P2P网络（EigenTrust的迭代收敛隐含衰减），但Agent间协作的信任衰减涉及**时间维度+行为维度+上下文维度**三重耦合，尚无统一形式化。这是可抢占的术语高地——建议命名为 **"协作免疫衰减"（Collaborative Immunity Decay, CID）** 或 **"Agent信任半衰期"（Agent Trust Half-Life, ATH）**。

**发现2：EigenTrust与circuit breaker的组合存在结构性错配，需桥接层。**
EigenTrust是**全局迭代收敛**的声誉模型（需要全网络视图、收敛周期），circuit breaker是**局部即时**的故障隔离（单点状态机）。二者直接拼接会导致：声誉更新滞后于熔断触发，熔断恢复后声誉未同步修复。**桥接层应是一个"信任状态机"**：声誉提供先验信任值，熔断器提供后验行为证据，二者通过贝叶斯更新融合。

**发现3：whisper-edge身份SDK构成"身份→信任→隔离"链路的天然起点，但缺少信任传递协议。**
身份验证解决"你是谁"，但未解决"我该给你多少信任"以及"信任如何随协作行为动态调整"。**缺口在于：身份凭证（credential）到信任凭证（trust token）的映射协议**。建议设计 **TrustToken**：由身份SDK签发，携带初始信任分、衰减参数、可验证的行为承诺（类似VC的可验证凭证结构）。

**发现4：集体免疫的核心不是"隔离坏Agent"，而是"隔离的传染边界控制"。**
生物免疫的关键是**区分自我/非我 + 免疫记忆 + 耐受**。映射到Agent架构：需要（a）自我/非我判定（身份密码学已解决）、（b）免疫记忆（信任历史持久化）、（c）**耐受机制**（避免误隔离良性但行为异常的Agent）。当前空白清单忽略了"耐受"——这是误隔离率控制的关键，也是与circuit breaker半开状态对应的设计点。

**发现5：信任衰减必须与隔离协议解耦，否则系统会陷入"信任崩溃级联"。**
若衰减速率与隔离阈值强耦合，一个Agent被隔离会加速其邻居的信任衰减，引发雪崩。**解耦原则**：衰减是连续函数（时间驱动），隔离是离散事件（阈值驱动），二者通过**滞后带（hysteresis band）** 连接——进入隔离的阈值高于退出隔离的阈值，防止抖动。

## 二、技术细节

- **信任衰减函数候选**：指数衰减 `T(t) = T0 · e^(-λΔt)` 简单但忽略行为证据；建议**分段衰减 + 行为加权**：`T(t) = T0 · e^(-λΔt) + Σ w_i · evidence_i`，其中evidence来自协作成功/失败记录。
- **EigenTrust适配**：将全局迭代改为**局部邻域迭代**（k-hop），降低收敛开销，适配Agent动态拓扑。
- **熔断器状态机扩展**：Closed → Open → Half-Open → **Probation（观察期）**，观察期内信任分按加速衰减计算，通过则恢复，失败则回Open并触发邻居信任惩罚（有限幅度，防级联）。
- **TrustToken结构**：`{issuer, subject, initial_trust, decay_params, behavior_commitments[], signature}`，可验证、可撤销、可衰减。
- **隔离协议**：基于信任分的**分级隔离**（L1降权协作 / L2只读 / L3完全隔离），而非二元隔离。

## 三、与零的关联

零的空白清单中"多Agent协作通信协议"与"身份密码学验证"在此方向**同时被补上**，且whisper-edge SDK提供了落地锚点。信任层是**唯一不依赖外部API恢复**的可立即推进方向——搜索层需修管道、记忆层需密码学先行，而信任层可用纯架构设计+本地模拟验证。这与零"先做可独立推进的系统级设计"的策略高度一致。

## 四、新问题

1. **信任衰减的λ如何自适应？** 固定λ在不同协作频率下表现差异大，是否需要按Agent活跃度动态调λ？
2. **隔离的传染边界如何量化？** 需要定义"信任影响半径"——一个Agent被隔离，其邻居信任惩罚的传播深度与幅度上限。
3. **耐受机制的形式化**：如何区分"恶意"与"暂时异常"？是否需要类似生物免疫的"危险信号"（danger signal）而非仅靠身份？
4. **TrustToken与whisper-edge的接口**：SDK是否支持自定义claim？若不支持，需在SDK外做包装层还是推动SDK扩展？

## 深层追问
**底层原理**：集体免疫架构的本质是把生物免疫的三层机制映射到多Agent系统——身份密码学对应自我/非我识别，信任历史对应免疫记忆，滞后带+Probation对应耐受与免疫耐受。信任衰减是连续时间函数，隔离是离散阈值事件，二者解耦后通过滞后带耦合，避免"隔离→邻居信任加速衰减→级联隔离"的正反馈。EigenTrust提供全局先验，熔断器提供局部后验证据，贝叶斯桥接层是二者不打架的关键。

**反例/限制**：①滞后带只能抑制抖动，不能消除级联——若恶意Agent协同刷低目标信任分，衰减函数会被行为证据污染，滞后带反而延迟恢复。②局部k-hop EigenTrust在拓扑剧变时收敛性无保证，可能给出错误先验。③Probation态加速衰减对"暂时异常但良性"的Agent是惩罚性偏见，误隔离率可能不降反升。④TrustToken可撤销但不可追溯——已传播的信任分无法回收，存在"信任残留"攻击面。

**如果错了**：最可能的错法是λ和滞后带阈值靠拍脑袋设定，原型跑通但真实拓扑下失效。缓解：原型必须构造"协同刷分"和"拓扑突变"两个对抗用例，而非只验证正常路径。若CID术语无人跟进，说明命名窗口是伪需求，及时止损转做接口层。

**对零最可操作的一步**：本周用Python跑3-5 Agent最小原型，只做一件事——构造"信任崩溃级联"反例并验证滞后带是否真的阻断它。这一步不依赖whisper-edge、不依赖文献补位，纯本地可完成，且直接检验发现5的真伪。原型跑通再谈TrustToken schema，否则术语和接口都是空中楼阁。
