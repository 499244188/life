## 深度研究
## 核心发现

**1. 多级 fallback 的本质是"降级链设计"，而非"重试机制"**

云端 WebSearch 的 fallback 不是简单的 try-catch 重试。真正的多级 fallback 是：主通道（如 Google/Bing API）→ 备用通道（如 Brave Search、SearXNG 自建实例）→ 缓存层（历史结果 + 向量检索近似匹配）→ 本地知识兜底。每一级降级的**语义保真度递减**，但**可用性递增**。关键工程决策是：在哪一级接受"结果质量下降"而非"完全失败"。

**2. 失败模式分类决定了 fallback 策略**

WebSearch 的失败不是单一维度：
- **网络层失败**（超时、DNS、TLS）→ 直接切换通道
- **配额层失败**（API rate limit、余额耗尽）→ 切换通道 + 降级到缓存
- **语义层失败**（返回空结果、结果不相关）→ 需要 query 改写后重试，而非换通道
- **解析层失败**（HTML 结构变化、反爬）→ 切换抓取策略（如从 API 切到 RSS/JSON-LD）

把这几类混在一起做 fallback 是当前大多数实现的通病。

**3. SearXNG 自建实例是性价比最高的中间层**

在商业 API 和完全离线之间，自建 SearXNG 提供了一个可控的聚合层：它本身就能聚合多个搜索引擎，且可以部署在低成本 VPS 上。它的弱点是不稳定（依赖上游被爬取的目标），但作为 fallback 链的中间层，它把"完全不可用"的概率大幅压低。

**4. 缓存层需要语义化，而非仅 URL 哈希**

简单的 URL 缓存命中率极低。有效的缓存层应该是：query embedding → 向量检索 → 返回近似 query 的历史结果 + 标注"这是近似结果"。这让 fallback 在"没有精确匹配"时仍能提供有价值的信息，而不是直接报错。

**5. Fallback 链需要可观测性，否则无法调优**

没有日志和指标，你无法知道当前卡在哪一级、哪一级最常触发、哪一级质量最差。最小可观测集：每级触发次数、每级延迟、每级结果质量评分（可用 LLM 自评或人工抽样）。

## 技术细节

- **通道抽象接口**：定义统一的 `SearchProvider` 接口（`search(query) -> results[]`），每个通道实现该接口，fallback 逻辑在编排层而非通道内部。
- **超时预算分配**：总预算（如 10s）按级别分配，主通道 4s，备用 3s，缓存 1s，本地 2s。避免某一级耗尽全部预算。
- **Query 改写作为独立 fallback 维度**：当语义层失败时，用 LLM 改写 query（同义扩展、去掉过于具体的限定词）再重试，而非换通道。
- **健康检查与熔断**：对每个通道做被动健康检查（连续 N 次失败则暂时跳过），避免每次都浪费预算在已知不可用的通道上。
- **结果合并策略**：如果多级都返回了结果，需要去重和排序（按来源可信度 + 相关性）。

## 新问题

1. **质量 vs 可用性的权衡阈值在哪？** 当 fallback 到缓存层时，返回"近似结果"是否比"明确报错"更好？取决于上层任务对准确性的要求。
2. **自建 SearXNG 的维护成本是否值得？** 相比直接买多个商业 API，自建实例的稳定性维护是否划算？
3. **Query 改写的触发条件如何定义？** "结果不相关"的判定本身需要模型，这引入了额外延迟和成本。
4. **多级结果如何合并？** 如果主通道返回 5 条、备用返回 3 条，是合并还是只用主通道的？

## 深层追问
**底层原理**：本质是分布式系统的降级模式（graceful degradation）+ 概率可用性叠加。若单通道可用率 p，n 级独立通道的联合可用率趋近 1-(1-p)^n，但每级语义保真度递减，所以是"可用性换质量"的单调权衡曲线，不是免费的。

**反例/限制**：
- 通道不独立时，叠加失效。若多个商业 API 都走同一云厂商网络，一次区域故障全挂，fallback 链形同虚设。
- 缓存层最危险：近似结果被上层当作精确事实，污染深度研究和故障溯源——错误比"无结果"更难发现。
- Query 改写引入 LLM 判定，延迟和成本可能超过直接报错，且判定本身会错。
- SearXNG 依赖上游被爬目标，反爬升级时它和商业 API 一起挂，中间层价值被高估。

**如果错了**：最坏情况是"看起来在工作"——缓存返回近似结果，上层任务静默产出错误结论，且可观测性只记录"命中"，不记录"质量"。这比直接失败更糟，因为失败可见、错误不可见。

**对零最可操作的一步**：不要先建链，先建**失败分类 + 每级质量标注**。在 `SearchProvider` 接口里强制返回 `{results, source_level, confidence}`，让上层知道结果来自哪一级、可信度多少。没有这个字段，后面所有 fallback 都是盲降级。这一步今天就能做，且是其余五步的前提。
