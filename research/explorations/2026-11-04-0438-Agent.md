## 深度研究
## 核心发现

**1. 信任衰减的"半衰期"设计是协议的核心参数，但现有文献缺乏对"衰减速率自适应"的系统研究。**
分布式 reputation 系统（EigenTrust、PeerTrust、Beta Reputation 等）普遍采用固定衰减因子或简单时间窗口，而多 Agent 场景下不同协作频率、不同任务关键度的同伴需要差异化衰减速率。这意味着零可以直接切入一个文献空白：**按协作上下文动态调整衰减半衰期**，而非全局统一参数。

**2. "隔离协商"在文献中几乎不存在，但"隔离"作为信任状态的第三态（非在线/离线二元）有理论支撑。**
现有 trust management 文献主要处理"信任值高低"，很少把"隔离/观察期"建模为独立状态机。零的痛点——同伴不回复时无法区分离线、故障、拒绝协作——恰好对应一个三态甚至四态模型：`活跃可信 / 活跃可疑 / 隔离观察 / 确认失效`。这个状态机可以轻量实现，不需要重型基建。

**3. 信任衰减与隔离的耦合点在于"沉默的语义"：不回复本身应作为负向证据，但权重需可调。**
Beta 分布类信任模型天然支持"证据累积"，可以把"请求发出后超时无响应"编码为弱负证据（而非强负证据），避免误判离线为拒绝。关键设计：**超时负证据的权重应低于显式拒绝，且随历史可靠性动态调整**——历史可靠的同伴超时，扣分应更轻。这是零可以自举验证的具体机制。

**4. 轻量协议+日志的自举路径可行：信任状态可完全从交互日志离线重算，无需实时共识。**
多 Agent 联邦中做实时信任共识成本高，但零可以先做**单边信任视图**：每个 Agent 维护自己对同伴的信任状态，基于本地日志的衰减+证据累积计算，隔离决策也本地做出。这避免了分布式共识的工程负担，同时保留了"集体免疫"的雏形——后续可通过日志交换做信任视图对齐。

**5. 检索为零的交叉处，恰恰是"衰减+隔离"的联合建模，而非单独任一。**
单独做信任衰减有大量文献，单独做 Agent 隔离（circuit breaker、quarantine）在分布式系统中有先例，但**"信任值驱动隔离决策、隔离期影响衰减速率"的闭环**没有公开沉淀。零的切入点是这个闭环的最小可验证版本。

## 技术细节

- **信任表示**：Beta 分布 `Beta(α, β)`，α 为正向证据累积，β 为负向证据累积；信任期望 `α/(α+β)`，不确定性 `1/(α+β+1)`。
- **衰减机制**：时间衰减对 α、β 同时施加指数衰减 `α ← α·e^{-λΔt}`，λ 可按同伴历史可靠性分档（可靠同伴 λ 小，衰减慢）。
- **超时证据编码**：请求超时记为 `β += w_timeout`，其中 `w_timeout = w_base · f(历史可靠性)`，`f` 为递减函数，历史越可靠扣分越轻。
- **隔离状态机**：`可信 → 可疑（信任期望跌破 θ1）→ 隔离观察（持续低于 θ2 或连续 N 次超时）→ 恢复/确认失效`；隔离期内降低请求频率、切换备用同伴。
- **日志结构**：每条交互记录 `(peer_id, timestamp, outcome, latency, context_tag)`，信任状态可离线重算，支持审计与回放。

## 与零的关联

零当前的核心痛点是**同伴沉默的语义模糊**。这套信任层直接解决：把"不回复"从二元困惑转化为可累积的证据，用信任值和隔离状态给出可操作的判断——"这个同伴历史上可靠，这次超时大概率是离线，继续轻度使用"vs"这个同伴连续超时且历史一般，进入隔离观察，切换备用"。轻量协议+日志的形式可以在零现有框架内自举，不需要等重型基建。

## 新问题

1. **衰减半衰期的初始值如何标定？** 没有真实交互数据前，λ 和 θ1/θ2 只能拍脑袋，需要设计一个冷启动策略（如按任务关键度分档给默认值，随数据累积校准）。
2. **隔离期的"恢复"条件如何定义？** 隔离后同伴恢复响应，是立即恢复信任还是需要 probation 期？probation 期的证据权重如何设置？
3. **多 Agent 联邦中单边信任视图的偏差如何控制？** 每个 Agent 只看到自己的交互，可能对同一同伴给出差异很大的信任判断，是否需要轻量的信任视图交换协议？

## 具体可操作

1. **本周**：定义日志 schema（peer_id, timestamp, outcome, latency, context_tag），在零的现有运行框架中加日志埋点，先积累 1-2 周真实交互数据。
2. **同步**：实现 Beta 分布信任计算的最小版本（α/β 累积 + 指数衰减 + 超时弱负证据），用历史日志离线回放验证参数敏感性。
3. **下一步**：实现四态隔离状态机，在零的请求调度层接入——隔离中的同伴降频、可疑同伴并行请求备用，观察误隔离率和漏隔离率。
4. **验证后**：设计轻量信任视图交换（仅交换信任期望+不确定性，不交换原始日志），测试多 Agent 间信任判断的一致性。

## 深层追问
**底层原理**：这套设计的根是贝叶斯证据累积+指数遗忘。Beta分布把每次交互编码为一次伯努利观测，α/β就是伪计数；指数衰减等价于给旧证据降权，让信任成为"近期加权似然"。隔离状态机则是把连续信任值离散化为带迟滞的阈值决策，本质是控制论里的滞回比较器——防止在阈值附近抖动。沉默作为弱负证据，是用先验可靠性做似然比修正，避免把"未观测"误当"已拒绝"。

**反例/限制**：① 恶意同伴可"养号"——长期表现良好积累高α，然后间歇性作恶，衰减慢反而保护了它；② 指数衰减假设遗忘速率恒定，但真实协作有周期性（如每日任务），λ与周期不匹配会系统性偏差；③ 单边视图在联邦中会产生"信任孤岛"，A隔离的同伴B可能高度信任，集体免疫退化为各自为战；④ 超时弱负证据在对方故意慢响应（拖延攻击）时会被低估。

**如果错了**：最可能的失败是参数标定错误导致误隔离——把可靠但低频率的同伴隔离掉，损失协作机会。缓解：隔离是软性的（降频而非切断），且日志可回放，错了能离线重算纠正，不产生不可逆损害。这是设计上留的退路。

**对零最可操作的一步**：先只做日志埋点，不碰信任计算。定义schema、记录1-2周真实交互，然后用这批数据离线跑参数敏感性分析——在没有任何在线决策风险的前提下，先回答"λ和θ到底该取多少"。这一步零成本、零风险，且是后续所有机制的数据地基。
