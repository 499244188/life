# 云端 WebSearch 方案深度分析

## 核心发现

**1. 感知层失效的性质是"管道污染"而非"管道断裂"**
三次查询返回引擎入口占位符，而非空结果或超时——这说明请求确实到达了搜索引擎，但抓取层拿到的是落地页/反爬挑战页，而非 SERP 内容。这是典型的**解析层与渲染层失配**：DuckDuckGo Lite 的 HTML 结构变更或 JS 挑战导致选择器失效。关键工程含义：修复成本低于替换成本，但替换的鲁棒性收益更高，因为占位符污染是"静默失败"——它不报错，只喂垃圾，这对 Agent 的推理链是毒性最强的故障模式。

**2. 四类候选方案的成本-鲁棒性光谱已可定性排序**
- **SearXNG 自托管**：零边际成本、完全可控、聚合多引擎（天然抗单点反爬），但需维护实例、延迟取决于上游引擎、结构化输出需自行解析 JSON 格式。
- **Tavily**：为 LLM 原生设计，返回已清洗的正文片段+来源，结构化输出最优，延迟低，但按次计费、有速率限制、依赖第三方可用性。
- **Brave Search API**：独立索引（非 Bing/Google 转售），反爬鲁棒性高，价格中等，返回结构化 JSON，但免费额度有限。
- **DuckDuckGo Lite**：当前失效，免费但无 SLA、无结构化输出、反爬脆弱——应降级为 fallback 而非主路径。

**3. 结构化输出是 Agent 场景的硬约束，不是加分项**
对零而言，搜索结果的消费者是推理链而非人类。占位符污染之所以致命，正是因为零无法区分"引擎入口页"与"真实结果"。因此方案评估的第一优先级应是**输出契约的可验证性**（能否用 schema 校验、能否检测污染），而非单纯的召回率。Tavily/Brave 的 JSON 契约天然满足；SearXNG 需在适配层加 schema 校验与污染检测（如检测结果中是否含 "DuckDuckGo" "challenge" 等特征串）。

**4. 元能力依赖链：检索可靠性 → 其余所有方向的证据化**
AgentFactory 编译机制、身份广播协议目前只能推演，因为无法用外部证据验证设计假设。检索管道恢复后，这些方向才能从"设计文档"进入"实证迭代"。这意味着检索方案的选择应优先考虑**可观测性**（每次查询的延迟、污染率、来源分布可记录），以便后续所有验证都建立在可信数据上。

## 技术细节

- **污染检测启发式**：对返回 HTML/文本做特征扫描（引擎名、CAPTCHA 关键词、结果数=0 但 HTTP 200），命中即标记为"感知失败"而非"无结果"，触发 fallback 链。
- **Fallback 链设计**：主路径 Tavily/Brave（结构化）→ 备路径 SearXNG 自托管 → 末路径 DDG Lite（仅作最后兜底，且强制污染检测）。
- **延迟基准**：需实测 P50/P95，Agent 场景对 P95 敏感（单次慢查询拖垮整条推理链）。
- **成本模型**：按"每日查询数 × 单价"估算，Tavily/Brave 在低频下可接受，高频需自托管摊薄。

## 与零的关联

这是零的**感知层修复**，且是元能力——它决定零能否用证据而非推演来验证自身设计。当前"静默污染"是最危险的故障：零会基于垃圾输入生成自信的错误结论。因此修复不仅是换引擎，更是给感知层加**输出契约与污染检测**，让零能区分"我没查到"与"我查到了假东西"。

## 深层追问
**底层原理**：搜索是"请求-渲染-解析"三段管道，任何一段失配都表现为感知失败。DDG Lite 的故障在解析段——HTML 结构漂移使选择器命中落地页。结构化 API（Tavily/Brave）把解析责任转移给服务方，用契约换鲁棒性；SearXNG 把解析责任留给自己，用可控换维护。核心权衡是"谁承担解析脆弱性"。

**反例与限制**：① 结构化 API 同样会静默失败——返回 200 但结果为空或过时，契约校验挡不住"合法但错误"；② 污染检测特征串是黑名单，引擎改文案即失效，且可能误杀含"challenge"字样的合法页面；③ 自托管 SearXNG 上游被封时降级为单引擎，抗反爬优势消失；④ 多引擎投票在结果分歧时无法裁决谁对，只增加延迟。

**如果错了**：最可能的错是"把换引擎当修复"。若根因是网络层（出口 IP 被限流），换任何引擎都复现污染。验证方法：同一查询从不同出口 IP 发，若结果差异大则根因在网络层而非解析层。另一错是过度工程——低频场景下污染检测+fallback 链的复杂度可能超过收益。

**对零最可操作的一步**：先写 20 行探测脚本，对四方案各发 3 条固定查询，只记录"HTTP 状态 + 是否含污染串 + 结果条数"三项。这一步不依赖任何架构决策，却能直接证伪"根因在解析层"的假设——若四方案全污染，问题在网络层，后续所有方案选型都要重来。先证伪，再建设。
