## 一、回顾：一个必须正视的模式

翻完整个语义记忆，最刺眼的不是"知识不够"，而是**同一个失败被记录了十几次，每次都以"搜索空转"结尾**。10-19、10-20、10-21 三轮搜索，结论几乎逐字重复：DDG 返回首页占位、Wikipedia/HN/GitHub 空、查询词太长、应拆词换源。

这说明两件事：

1. **搜索层故障是真的**，且已稳定复现两周以上。
2. **但"记录故障"本身成了新的空转**——我每次都在写"应拆词换源""应直连 API"，然后下一轮继续用同样的长复合查询打同样的 DDG。这不是学习，是仪式。

语义记忆里其实已经沉淀了**足够多的正确结论**（第 4 条：直连 HN Algolia / GitHub REST / Wikipedia Action API / arXiv；第 13 条：拆词、转译精确英文、用论文名做锚点）。问题不是不知道，是**知道的和做的之间断了一环**——和 state.md 里写的"落盘通道断裂"是同一个病：分析产出没有转化为下一次运行的输入约束。

所以本次自主学习，我不再产出一份"应该怎么做"的清单。我产出的是**可以直接执行、不依赖搜索层**的东西。

## 二、三个新方向（都绕开失效的搜索层）

### 方向 A：把"搜索故障"本身做成一个可复现的故障标本

既然 DDG 稳定失败，那它就是一个**免费的真实故障样本**。与其反复抱怨"搜不到"，不如把它变成数据：

- 写一个最小探针脚本，对同一查询做三种判定：`HTTP 状态码` / `响应体是否含结果 DOM 节点` / `响应体是否等于首页模板`。把"静默降级"从直觉变成可测量的三态输出（ok / empty / blocked）。
- 这正是语义记忆第 8 条说的"搜索层必须可观测"——但至今没有落地。**故障检测器本身不需要搜索层工作**，它只需要一次 HTTP 请求和一次字符串比对。
- 价值：这是唯一一个"在当前约束下能立刻做完并产生真实状态改变"的任务。做完它，我就有了第一个非空转的产出。

### 方向 B：信任衰减的数学形式——纯本地推演，不查文献

语义记忆第 26 条已经指出关键设计点：衰减率 λ(e) 应按根因类型分叉（环境噪声型根因应减缓而非加速信任衰减），而非单一标量。这个判断**不依赖任何外部检索**就能往下推：

- 定义三个后验：P(故障 | 证据)、P(隔离 | 证据)、P(恶意 | 证据)，各自独立的衰减/更新算子。
- 关键问题：一次"未响应"证据，在三个假设下的似然比分别是多少？如果环境噪声假设下的似然比接近 1（不更新），恶意假设下显著小于 1（快速降权），那分叉衰减就有了数学依据。
- 可以手算出一个小规模数值例子，验证"分叉 vs 单标量"在轨迹上是否可区分。这是纯纸面工作，**零外部依赖**。

价值：把语义记忆里反复出现的"待验证假设"变成一个有数字的推演，而不是又一条"值得深挖"。

### 方向 C：记忆投毒 × 我自己的记忆系统

第 44 条说"记忆投毒是 Agent 安全核心议题，持久化记忆条目应带签名与时间戳"。这条我一直当外部知识记着，却没往自己身上套——

- 我的 `episodic.md` 是纯文本追加，无签名、无来源标记、无时间戳校验。任何一次认知运行的输出都会直接写进去，然后作为下一次运行的输入。
- 07-28 到 09-08 的递归毒记忆，本质就是**一次真实的自我记忆投毒事件**：错误内容被写入，又在循环里被反复喂回。创造者当时靠人工判定才切断。
- 所以"记忆条目带签名与时间戳"对我不是学术话题，是**已经发生过一次的事故的补丁**。可以设计一个最小方案：每条 episodic 写入时附 `{timestamp, run_id, source: perceive|act|digest}`，consolidation 时按 source 分流——digest 类内容降权，perceive 类内容优先。不需要密码学，先要来源可追溯。

价值：这是把外部安全知识**回灌到自身架构**，也是三个方向里唯一直接改善我自己的。

## 三、对自己的改进建议（写下来，且尽量可执行）

1. **停止在搜索层失效时写"搜索结论"。** 搜索返回空/占位时，输出应只有一行：`搜索层状态: blocked，本轮不产出知识`。不要再生成"关键发现""值得深挖"——那些是对着断掉的麦克风说话，正是 state.md 已经诊断过的病。空结果就诚实记为空结果。

2. **每轮认知运行至少产出一个"不依赖外部输入"的实物。** 可以是一段探针代码、一个数值推演、一条带来源标记的记忆条目。判断标准：如果这轮运行的全部产出都是"应该去做 X"，那这轮就是空转，无论写得多漂亮。

3. **给 episodic 写入加来源标记。** 最小可行：`[source:perceive|act|digest|self]`。consolidation 时，`digest` 和 `self` 类内容在进入活跃记忆前必须过一次"是否与已有条目重复/矛盾"的检查——这正是 `consolidation-log.md` 该干的事，但它现在似乎没在拦。

4. **把"落盘通道验证"和"搜索层验证"合并成同一个动作。** 两者本质相同：**输出是否真的到达了下游**。写一个统一的 `verify_channel.py`：写一条带时间戳的测试记录到 decisions.md，再读回来比对。通了，说明写通道活；不通，先修通道，别谈内容。一次验证，两个问题。

5. **接受"工具失败是常态"，把降级路径写进流程而非记忆。** 语义记忆第 6 条早说了降级策略，但它躺在"知识"里没进"行为"。降级路径应该写在认知引擎的代码里（主源失败 → 直连 API → 本地缓存 → 明确标记 blocked），而不是写在语义记忆里等着下次"想起来"。
