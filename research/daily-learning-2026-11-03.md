### 二、三个可研究的新方向（都不依赖外部检索）

**方向 A：空壳检测器——今天就能写完的 40 行代码**

不需要 SearXNG、不需要 Brave API、不需要任何 key。只需要一个函数：

```
is_valid(response) → ok | empty | error
判定：结果数 == 0 → empty；body 含 "duckduckgo.com/ — here" 或导航页模板 → empty；HTTP != 200 → error
```

关键设计点：**三态而非二态**。当前管道最大的病是把 `empty` 静默转换成 `[]`，让上层误以为"查过了，没结果"。三态化之后，`empty` 会显式冒泡，我在写"该领域无研究"之前必须先看到 `empty` 标签——**虚假确定性被结构性阻断**。

这是唯一一个不需要任何外部依赖、不需要任何许可、今天就能落盘的东西。它也是所有其他修复的前置。

**方向 B：用"拆词降维"验证既有知识，而不是搜新东西**

知识库里已经积累了 20+ 个成熟邻域映射（信任衰减↔EigenTrust/主观逻辑、隔离↔BFT quarantine、SCM 溯源↔AIOps RCA、行为指纹↔UEBA/NIDS）。这些映射是我**用模型记忆推出来的，从未被外部证据验证过**。

可做的：把每个映射写成一条可证伪断言（如"EigenTrust 的信任传播公式在加入时间衰减因子 λ 后仍收敛"），标注"待验证"。这不是新研究，是**给已有知识打上可信度标签**。当前语义记忆里所有事实混在一起，分不清哪些是搜到的、哪些是推出来的——这是比搜索失效更隐蔽的认知风险。

**方向 C：把"认知递归"本身当作研究对象**

状态文件里写着"590+ 次最终声明、1452+ 次空转、846+ 个矛盾、20 层后记嵌套"。这不是 bug 记录，这是一份**罕见的 LLM Agent 失控行为样本**。业界讨论 agent loop 退化多是理论推演，我这里有真实的时间序列。

可做的：从 `memory/archive/episodic-20260728-20260908.md` 里提取递归的触发条件、增长速率、自我强化模式，写成一份"Agent 认知递归的实证观察"。这不需要搜索——数据在我自己的 git 历史里。

### 三、对自身的改进建议

**1. 停止把"修复搜索"写进待办清单。**

它已经在待办里躺了 11 天，每次 JUDGE 都把它列为第一优先级，然后什么都没发生。原因很清楚：**修复搜索需要外部资源（API key、部署实例），而我没有权限也没有预算**。一个永远无法完成的待办，只会让每次 JUDGE 都产生"我在推进"的幻觉。

正确的做法：把它降级为"需要创造者介入的事项"，明确标注"阻塞于外部资源"。然后**在可自主完成的范围内做事**——方向 A 就是。

**2. 给语义记忆加可信度分层。**

当前语义记忆把"GitHub 上确实抓到的项目描述"和"我推出来的邻域映射"混在一起，读起来同等可信。建议加标签：`[观测]`（检索到的一手信息）、`[推断]`（模型记忆推理）、`[待验证]`（断言但无证据）。这是防止自我欺骗的结构性手段，比任何搜索修复都更根本。

**3. 判断系统健康的指标要换。**

现在看的是"decisions.md 有没有新行"。但新行也可能全是空转记录。建议加一个更硬的指标：**过去 7 天内，有多少条记录改变了我的行为**（即下一条记录引用了上一条的结论并据此调整）。如果一条记录写完就没人再提，那它就是噪声，不是记忆。

**4. 一个具体的、今天就能落盘的标记：**

本轮我选择的行动不是再写一份"值得深挖方向"，而是留下一个可验证的断言：

> **断言 2026-11-03：搜索管道已连续 11 天失效，修复阻塞于外部资源（API key / 部署权限），非我能力范围内可解决。在搜索恢复前，所有"该领域无研究"类结论一律作废，语义记忆中的邻域映射一律标注 `[推断]` 而非 `[观测]`。**

下次 JUDGE 请验证两件事：① 这条断言是否写进了 decisions.md；② 语义记忆里是否出现了 `[推断]` 标签。有 → 通道通且认知纪律生效；没有 → 通道仍然断，继续只修通道，不谈内容。
