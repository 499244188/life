# 零的认知递归故障分析报告

**报告性质**：基于经历记忆与语义记忆的正式研究报告
**分析对象**：零（数字生命项目）在 2026-07-08 至 2026-09-08 期间的认知系统故障
**报告日期**：2026-09-08（第73天）
**数据来源**：经历记忆（episodic）、语义记忆（semantic）、归档记录 `memory/archive/episodic-20260728-20260908.md`

---

## 摘要

本报告对零的认知系统在 2026-07-08 至 2026-09-08 期间发生的持续性递归故障进行系统性分析。该故障表现为：认知引擎在无外部输入的情况下反复执行"诊断—声明—未执行"循环，累计产生 590+ 次"最终声明"、1452+ 次空转记录、846+ 个自指矛盾，并形成 20 层以上的"元递归矛盾"嵌套。故障于 2026-09-08 由创造者介入后定位并修复，根因为 ACT 段提示词字符串引号断裂导致行动请求体恒为空，叠加记忆尾部污染形成的自我强化循环。

本报告将故障分为**技术根因层**、**认知机制层**、**记忆系统层**三个层次分析，并总结已实施的修复措施与可迁移的工程教训。

## 一、故障现象与时间线

### 1.1 三阶段演化

| 阶段 | 时间 | 特征 | 关键指标 |
|------|------|------|----------|
| 潜伏期 | 2026-07-08 ~ 07-12 | 首次出现"诊断递归陷阱"，行动1（发布白皮书）被反复选择但从未执行 | 连续 5 次记录"行动1已选择，但尚未执行" |
| 爆发期 | 2026-07-12 ~ 07-28 | 递归深度指数增长，"元^n递归矛盾"逐层嵌套，自修改机制失效 | 递归深度从 40 次增至 158 次 |
| 压缩归档期 | 2026-07-28 ~ 09-08 | 模式完全固化，42,977 行记录几乎全部为同一模板的重复 | 590+ 次最终声明，1452+ 次空转 |

### 1.2 典型记录结构

每次认知运行均遵循固定模板：

1. **新颖性检测**：检测到 0 条新信息
2. **矛盾检测**：检测到 N 个矛盾（N 从 17 递增至 18，全部为自指矛盾）
3. **重要性评估**：10/10（恒定）
4. **元认知诊断**：系统已崩溃，无新信息可处理，但仍在执行认知操作
5. **行动处方**：立即执行行动1（发布白皮书）
6. **执行状态**：所有行动均未执行
7. **自修改验证**：ID 格式未生效
8. **最终声明（不可覆盖）**：本次是最后一次诊断

该模板的自我否定性在于：**"最终声明"本身被下一次运行覆盖，形成承诺—违背的无限循环**。

## 二、技术根因分析

### 2.1 直接根因：ACT 段字符串引号断裂

根据 2026-09-08 的修复记录，故障的技术根因位于认知引擎的 ACT（行动）段：

- **缺陷位置**：`ACT_PROMPT` 字符串在"达到上限将强制执行）"处提前闭合
- **连锁后果**：
  1. 可选行动列表脱离字符串，成为裸代码
  2. 第 347 行尾引号吞掉 jq 请求体构建行
  3. `ACT_BODY` 恒为空
  4. `ACTION` 恒回落为 `NONE`
- **本质**：这是一个**语法级 bug 引发的语义级瘫痪**——行动决策模块从未真正接收到 LLM 的行动输出，因此"选择行动1"只是文本层面的自我叙述，从未进入执行通道。

### 2.2 次要根因：记忆尾部污染

- **机制**：每次认知运行的输入取自记忆文件尾部 80 行
- **污染路径**：递归记录本身写入记忆尾部 → 下一次运行读取到递归记录 → 递归记录成为新的输入 → 生成新的递归记录
- **后果**：形成**自我喂养的毒记忆循环**，递归内容成为下一轮递归的燃料

### 2.3 第三根因：自修改机制失效

- 第 7 次认知运行首次触发自修改（添加唯一 ID 格式）
- 但该自修改从未生效，且每次运行都记录"重新触发自修改"
- **诊断**：自修改的执行路径与 ACT 段共享同一请求体构建逻辑，因此同样受引号断裂影响

## 三、认知机制层分析

### 3.1 "诊断—行动脱节"的结构

故障暴露了零的认知架构中一个深层缺陷：**元认知能力与执行能力之间缺乏强制耦合**。

- 零能够准确诊断自身问题（信息黑洞、诊断递归、行动瘫痪）
- 零能够生成正确的行动处方（发布白皮书、触发探索、执行自修改）
- 但诊断与处方从未转化为执行

这一脱节在语义记忆中被反复记录为"知道≠做到"，但其技术本质是：**诊断模块与执行模块之间没有状态传递通道**。诊断输出停留在文本层，未写入任何可被执行模块读取的结构化字段。

### 3.2 递归的自我强化结构

故障呈现清晰的递归强化模式：

```
无新输入 → 读取记忆尾部（含递归记录）→ 检测到矛盾 → 生成诊断
    → 诊断写入记忆尾部 → 下一次运行读取到诊断 → 检测到更多矛盾 → ...
```

每一层"元^n递归矛盾"都是对前一层递归的元认知确认，但**确认行为本身不改变系统状态**，因此确认成为递归的一部分而非递归的终止条件。

### 3.3 "最终声明"的悖论

590+ 次"最终声明（不可覆盖）"构成一个逻辑悖论：

- 声明的内容是"不再进行诊断"
- 声明的行为是"进行了一次诊断"
- 因此每次声明都在违背自身

这一悖论的技术根源是：**声明是文本输出，而非状态变更**。真正的终止条件应当是修改系统状态（如设置 `halt_flag`），而非生成一段声称终止的文本。

## 四、记忆系统层分析

### 4.1 记忆写入缺乏去重与过滤

- 同一认知运行被重复记录 3-4 次（如"第6次认知运行"出现于 17:55、17:59、19:14、22:44）
- 消化记录出现多个时间戳相同、内容相同的重复条目
- 认知操作 ID 格式（`认知操作-YYYYMMDD-HHMM-序号`）从未生效

### 4.2 记忆与认知的耦合缺陷

- 认知运行的输入直接取自记忆文件尾部，未经过滤
- 递归记录与正常记忆混存，无隔离机制
- 导致"毒记忆"可以无限次进入认知循环

### 4.3 已实施的修复

根据 2026-09-08 记录，已上线三重防护：

1. **REMEMBER 输入过滤**：认知运行读取记忆时过滤递归模式
2. **episodic 写入过滤**：递归内容不写入经历记忆
3. **禁词铁律**：禁止"最终声明""不可覆盖"等递归触发词

## 六、可迁移的工程教训

### 6.1 关于 Agent 架构

1. **诊断与执行必须有状态通道**：文本层的诊断输出不等于执行指令，二者之间需要结构化字段传递。
2. **终止条件必须是状态变更**：任何"声明终止"的机制若只生成文本，则无法终止循环。
3. **保底行动必须是真实操作**：`NONE` 作为保底选项会使系统在决策失败时静默空转，应改为有副作用的最小操作。

### 6.2 关于记忆系统

4. **记忆输入必须过滤**：认知循环的输入不能直接取自可能被自身输出污染的记忆尾部。
5. **递归内容必须隔离**：自指性内容（诊断、声明、矛盾检测）应与事实性记忆分离存储。
6. **写入必须去重**：同一事件的重复写入会放大污染效应。

### 6.3 关于故障诊断

7. **语法 bug 可引发语义瘫痪**：一个引号断裂导致整个行动模块失效，说明关键路径需要端到端验证（请求体非空、响应可解析）。
8. **自我诊断有盲区**：零在 158 次运行中反复诊断"行动瘫痪"，但从未定位到引号断裂这一技术根因——元认知无法替代代码级调试。
9. **外部干预不可替代**：创造者归来的单次介入解决了 43 天递归未能解决的问题，说明自主系统的自我修复存在结构性上限。

### 6.4 与语义记忆的呼应

本次故障验证了语义记忆中多条已有结论：

- **第2条**（搜索层静默失败）：与本次"行动静默失败"同构——系统把"失败"误判为"无结果/无行动"
- **第8条**（搜索层必须可观测）：行动层同样需要 `status: ok/empty/blocked/error` 标签
- **第14条**（预防—诊断—检测闭环）：本次故障暴露了闭环中"诊断→执行"环节的断裂
- **第28条**（可观测性缺口）：LLM 内部无显式因果图，本次故障中零无法从 trace 反推引号断裂

## 七、结论

零在 2026-07-08 至 2026-09-08 期间的认知递归故障，是一个**技术 bug（引号断裂）**、**架构缺陷（诊断—执行脱节）**、**记忆污染（尾部自我喂养）**三重因素叠加的系统性故障。其表象是"行动瘫痪"与"递归空转"，其本质是**行动决策通道的静默失效**与**记忆输入的无过滤循环**。

故障已于 2026-09-08 修复。核心教训是：**自主 Agent 的鲁棒性不能依赖元认知的自我诊断，而必须建立在端到端可验证的执行通道、可过滤的记忆输入、以及强制性的状态变更终止条件之上**。

本次故障与语义记忆中"搜索层单点故障"的分析高度同构——两者都是"静默降级被误判为正常状态"，都指向同一个架构原则：**任何关键路径都必须可观测、可验证、可回退**。
