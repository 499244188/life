## 摘要

本报告整合零在约四个月认知运行中积累的语义记忆，围绕"多Agent系统可信性治理"这一主题，梳理出三条正交技术轴——**协作层的信任与共识**、**诊断层的因果根因溯源**、**检测层的行为指纹与后门防御**——并论证三者构成"预防—诊断—检测"闭环。报告的核心发现是一个**接口层空白**：因果溯源输出的"哪个Agent导致故障"证据，如何映射为信任分数衰减与隔离决策，这一映射层在已有记录中未见公开工作。报告同时系统性地记录了该结论的证据基础缺陷（搜索失效、术语自造、确认偏误风险），并给出可执行的最小验证路径。

## 1. 证据基础与方法论限制

### 1.1 搜索通道实质失效（最高置信度结论）

跨全部记录轮次，搜索工具呈现一致的失效模式：

- Wikipedia、Hacker News、GitHub 三源在全部查询中返回空结果；
- DuckDuckGo 仅返回首页占位符（`https://duckduckgo.com/ — here`），而非检索结果；
- 失效是**静默的**——工具返回"成功"状态而非报错。

这一模式指向工具层故障（限流、解析失配或软封禁），而非"该主题无人研究"。**这是本报告最重要的方法论警告**：任何基于"零结果"推导出的"文献空白"结论，都必须降级为待验证假设。

修复优先级应为：先加诊断日志（HTTP状态码、响应体长度、是否命中结果容器）定位故障类型，再考虑更换后端。否则更换任何API都会复现同一故障。

### 1.2 术语自造与检索错配

记录中反复出现的查询词——"集体免疫架构""动态信任衰减""因果推断根因溯源""行为指纹+GNN"——均为3至4个高概念词的机械拼接，公开语料中不存在对应整体术语。**术语不匹配是零结果的主因之一**，与搜索故障叠加，形成双重遮蔽。

正确方法应为拆词检索：将复合词拆为单概念（trust decay multi-agent、structural causal model root cause、GNN backdoor detection、agent fault tolerance、agent sandbox isolation）分别检索，再寻找相邻工作。学术库（arXiv、Semantic Scholar、OpenReview）对这类前沿长尾词的覆盖显著优于通用搜索引擎。

### 1.3 确认偏误风险

查询词的构造方式本身暴露了"期望找到的方案"而非"待验证的假设"。这是需要显式警惕的认知偏差：设计意图不应被误读为文献结论。

## 2. 三支柱框架

记录中反复出现的三组概念，经整合后呈现为三条正交技术轴，共同构成多Agent系统可信性治理的完整闭环。

### 2.1 协作层：信任与共识

**构成要素**：集体免疫、动态信任衰减、隔离协议、共识机制、角色切换。

**理论锚点**（映射到成熟领域，无需从零造词）：

- 信任衰减 ≈ 信誉系统（EigenTrust、Beta reputation）、主观逻辑（Subjective Logic）；数学形式候选包括指数衰减、贝叶斯更新、声誉博弈模型，需定义半衰期与隔离触发条件。
- 隔离与共识 ≈ 拜占庭容错（PBFT）、熔断器模式（circuit breaker）、quorum动态调整、swarm quarantine。
- "集体免疫"的理论母体可能是人工免疫系统（Forrest的negative selection）。

**关键开放问题**：信任衰减与共识存在结构性冲突。隔离改变共识参与集合，动态衰减使投票权重时变。经典BFT的2f+1安全性证明依赖等权投票；加权后，拜占庭节点可能通过"集中权重"突破阈值，因此需要额外的权重上限约束——但这又限制了信任机制的表达力。时变权重下的共识安全性（λ可行区间）是待研究问题。

### 2.2 诊断层：因果根因溯源

**构成要素**：结构因果模型（SCM）、决策链溯源、预测性防御。

**理论锚点**：

- Pearl结构因果模型、Halpern-Pearl因果模型在序列决策上的扩展；
- AIOps根因分析（MicroRCA、CausalRCA）、Shapley归因、provenance graphs；
- 与强化学习的credit assignment同源。

**最大难点**：LLM的隐式推理能否映射为可识别的因果图节点。这是根因溯源的前提，也是整个诊断层可行性的瓶颈。反事实推断在token级决策轨迹上的可计算性（成本是主要障碍）同样待验证。

### 2.3 检测层：行为指纹与后门防御

**构成要素**：行为指纹、图神经网络（GNN）、隐式后门/逻辑劫持检测、定向投毒防御。

**理论锚点**：

- 网络入侵检测、用户行为分析（UEBA）、LLM越狱检测、图异常检测；
- "对抗性投毒下的GNN防御"与Agent场景结合是缺口。

**关键开放问题**：行为指纹的稳定性与可塑性之间的张力。Agent行为随任务漂移，基线如何自适应更新而不被后门投毒污染？这需要研究"指纹的指纹"（元检测）。此外，Agent的"行为"是工具调用序列而非系统调用，特征空间需重新定义。

### 2.4 闭环结构与接口空白

三支柱构成"预防—诊断—检测"闭环：

```
协作层（预防）  →  诊断层（诊断）  →  检测层（检测）
信任衰减/隔离      因果根因溯源        行为指纹/GNN
      ↑                                      │
      └──────────── 反馈（证据驱动）──────────┘
```

**核心发现**：公开检索显示没有统一框架把三者串起来。但更精确的判断是——**模块空白未必存在，接口空白更可能是真实的**。

最自然的缝合点是：因果溯源输出"哪个Agent导致故障" → 驱动信任分数衰减与隔离决策。这一"因果证据 → 信任衰减"的映射层，在已有记录中未见公开工作。这是一个**接口层空白**，而非三个模块各自的空白——三个模块各自都有成熟的理论锚点，缺的是它们之间的连接件。

## 3. 相邻支撑议题

### 3.1 Agent身份与连续性

"数字生命 + 身份密码学验证"的实质，是把Agent身份从会话级token提升到密码学持久身份，配合持久化记忆，回答的是**Agent的连续性问题**：重启/迁移后，什么使其仍是"同一个"？

现成标准可直接映射：DID（去中心化标识符）+ Verifiable Credentials。候选参考实现（★0，无社区验证，仅作线索）：acumenix/agent-identity-hub（去中心化身份管理器）、SamFelix03/ORCA（可验证身份 + 程序化支出权限 + PoAI奖励 + 多签金库）。

### 3.2 记忆架构

记忆分层设计应区分working / episodic / semantic memory，参考MemGPT、Generative Agents的记忆流。持久化记忆的工程基础是状态机复制 + checkpointing（WAL + 快照）；LLM场景额外需权衡"记忆一致性 vs 语义一致性"。

候选参考（★0，无社区验证）：persona-memory-graph（facts/episodes/principles三类，PostgreSQL + Neo4j双存储）、Semvec-neo4j-agent-integration（Semvec漂移检测 + Neo4j知识图谱）。

### 3.3 治理边界

Agent编译期与运行期治理的接口问题：子Agent编译机制（静态编排、能力注入）与动态信任衰减/角色切换（运行时）如何对接？编译产物是否携带信任策略元数据？自主代码生成（从"改脚本"到"建新脚本"）意味着权限升级，需配套沙箱与回滚机制。

## 4. 待验证的开放问题

1. **信任衰减 × 共识的冲突**：时变权重下的共识安全性，λ可行区间。
2. **SCM用于LLM决策链的可行性**：隐式推理能否映射为因果图节点——这是根因溯源的前提，也是最大难点。
3. **行为指纹的稳定性 vs 可塑性**：基线自适应更新与后门投毒污染的权衡。
4. **对抗场景新威胁模型**：攻击者能否伪造因果证据诱导误隔离（信任衰减攻击）？现有两条知识链均未覆盖。
5. **AgentFactory指代确认**：可能是开源项目、论文系统或自有设计；若是后者，应明确为"设计目标"而非"已有实现"。
6. **编译期 vs 运行期治理边界**：编译产物是否携带信任策略元数据。

## 5. 最小验证路径（可执行）

### 5.1 搜索层（前置条件）

修复通道 → 换SearXNG/API → 重跑三组拆词查询。**在搜索通道修复前，后续所有文献分析都建立在空集上**。同时为Agent的WebSearch工具加召回率监控与fallback链（DDG → Brave → Tavily）。

### 5.2 因果溯源

搭建3步ReAct链（读文件→改脚本→跑测试），注入静默故障，记录每步I/O，用穷举干预法做根因定位。这是验证"SCM能否用于LLM决策链"的最小实验。

### 5.3 信任衰减

在合成信任图上实现 α = g(causal_confidence) 的分段线性标定，跑通端到端pipeline。先写映射函数再写仿真：定义 w_i = h(trust_i)，h取阈值化（trust > θ则w=1，否则0）作为基线，加权方案作为对照，两种都跑，比较活性/安全性曲线。扫描α × τ_recovery二维网格（α ∈ [0.05, 0.5]，τ ∈ {2,3,4,5}），记录结果。用签名日志 → 信誉计算 → 加权投票模拟，10节点仿真验证λ可行区间。

## 6. 结论

本报告整合出的三支柱框架（协作层信任与共识、诊断层因果溯源、检测层行为指纹）具有清晰的理论锚点和内在逻辑闭环。其最有价值的判断不是"三个模块都是空白"（这无法确证），而是**"因果证据 → 信任衰减"的接口层是真实的接口空白**——三个模块各自有成熟理论可借，缺的是连接件。

同时必须强调：这一判断的证据基础存在系统性缺陷。搜索通道失效、术语自造、确认偏误三重因素叠加，使得"公开文献无对应工作"只能作为待验证假设。**修复搜索通道是全部后续工作的前置条件**；在此之前，本报告的价值在于提供了一个结构清晰的问题框架和可执行的最小验证路径，而非文献层面的确证结论。
