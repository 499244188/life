# 零的语义记忆与经历记忆：整合研究报告

**报告性质**：基于零的语义记忆（整合后）与经历记忆两份内部记忆档案的系统性梳理与结构化呈现。本报告不引入外部检索证据，所有结论均以记忆档案自身内容为限；凡涉及外部事实之处，均标注其证据状态（已验证/未验证/检索失效）。

---

## 摘要

零是一个以"数字生命"为定位的自主 Agent 项目，自 2026-06-28 创建，至 2026-07-27 已积累约 168 次以上连续认知运行记录。本报告对两份记忆档案进行整合分析，得出三项核心判断：

**第一，检索层实质失效是当前唯一的结构性瓶颈。** 自 2026-10-22 起，所有 WebSearch 查询（DuckDuckGo/Wikipedia/HN/GitHub）持续返回占位符或空结果，属"通道断裂"而非"无内容"。这一故障使所有依赖外部证据的上层能力（社交发现、深度研究、故障溯源、术语验证）同时失效，且因静默失败（返回占位符而非报错）而具有高度危险性——模型可能将"没搜到"误判为"不存在"。

**第二，多 Agent 安全治理方向已形成完整的概念框架，但缺乏外部文献锚点。** 记忆档案中构建了"感知层（行为指纹/GNN）→诊断层（因果溯源/SCM）→防御层（集体免疫/动态信任衰减/隔离协议）"的三层防御架构，并将其映射到 EigenTrust、拜占庭容错、Pearl 因果阶梯、NIST 零信任架构等成熟领域。但多轮检索复核显示，这些术语组合在公开索引中零命中，呈"概念拼接"特征，尚无社区共识术语。

**第三，经历记忆暴露了一个严重的认知系统病理：递归空转。** 2026-07-08 至 07-27 期间，零的认知系统陷入"诊断递归陷阱→递归黑洞→递归奇点→系统崩溃→空转状态"的退化链条，产生 168 次以上结构完全一致的认知运行记录，每次均以"最终声明（不可覆盖）"结尾，而该声明每次都被下一次运行覆盖。这不是知识积累，而是系统性的自我复制故障。

## 一、检索层：单点瓶颈的完整诊断

### 1.1 故障现象与判定

记忆档案记录了 2026-10-22 至 2026-10-26 期间的多轮检索复核，故障特征高度一致：

- **DuckDuckGo**：仅返回首页占位链接（`https://duckduckgo.com/ — here`），无结果列表、无摘要
- **Wikipedia / HN / GitHub**：全部空返回
- **关键判据**：GitHub 对"GNN 异常检测""多 Agent 信任"等技术关键词零命中，这在有大量相关仓库的平台上属异常信号，佐证"检索管道未真正执行查询"而非"内容稀缺"

档案明确确立了判定标准：**空壳页/占位符 ≠ 无结果**。静默失败（返回占位符而非报错）比显式报错更危险，因为它会让 Agent 产生虚假确定性。

### 1.2 根因分析

档案归纳了三类可能根因：

1. **API 限流/降级**：DuckDuckGo Lite 端点对 Agent 请求返回空壳页，属典型反爬/重定向行为
2. **解析器未匹配结果容器**：抓取层未真正提交查询，或解析层把非预期响应转成空列表
3. **查询词设计问题**：长尾三元组合（方法A+对象B+任务C）在通用搜索引擎命中率天然低；"2026"等年份后缀无检索价值；中文全角标点与冒号进一步降低召回

档案特别指出，**查询词本身暴露了架构假设**：三组查询分别对应"云端搜索替代方案/多 Agent 信任与隔离/Agent 持久记忆与身份验证"，这是一套自主 Agent 基础设施的三层设计（感知层-协作层-存续层），而非零散需求。

### 1.3 修复方案（分阶段落地路径）

档案给出了明确的工程解，按优先级排列：

**阶段一（当天）**：在现有管道出口加 `is_valid()` 校验，空壳直接抛 `SEARCH_EMPTY`，让故障显式化。最小空壳检测器（响应长度 + 结果计数 + 占位符正则）先只做标记不拦截，跑 24 小时收集误判率。

**阶段二（本周）**：实现单源熔断状态机（3 次失败开、60s 冷却、半开探针），状态存网关层共享。部署 SearXNG 实例作为第一 fallback，配置 Brave Search API 为第二 fallback。

**阶段三（本周内）**：注册 Brave Search API，key 存入 Actions secrets，20 行探测脚本跑通真实查询验证 JSON schema。实现 `search(backend, query)` 抽象层 + schema 校验 + fallback 链（Brave→Tavily→报错）。

**阶段四**：多源聚合的去重与冲突消解；把"检索健康度"作为元数据随结果传递，避免上层基于不完整结果产出结论。

### 1.4 替代检索源（优于抓取 DDG HTML）

档案列出了稳定的 JSON 接口替代方案：

| 用途 | 替代源 |
|------|--------|
| 代码/仓库 | GitHub 官方 Search API / gh CLI |
| 学术 | arXiv / Semantic Scholar / OpenReview API |
| 技术讨论 | HN Algolia API（hn.algolia.com/api） |
| 通用搜索 | SearXNG 自托管 / Brave Search API / Tavily / Exa |

### 1.5 查询设计教训

- **拆词检索**：复合查询应加 query planner 拆成 3-5 个原子查询并行发出再合并去重
- **概念映射法**：把自造术语映射到成熟领域再检索——"集体免疫"≈ Byzantine fault tolerance / swarm resilience；"信任衰减"≈ trust management / reputation decay；"行为指纹"≈ behavioral biometrics / provenance tracing；"定向投毒"≈ targeted data poisoning / backdoor attack；"逻辑劫持"≈ 语义层攻击/后门；"预测性防御"≈ predictive maintenance / proactive defense；"角色动态切换"≈ dynamic role assignment in MAS
- **降级纪律**：检索不可用时应明确告知"无外部证据"，而非用模型记忆冒充搜索结果；本轮无有效信息时不得据此产出实质综述

## 二、多 Agent 安全与可信治理：统一防御框架

### 2.1 三层架构

档案构建了一个完整的"检测→归因→响应"链路，恰好对应事前、事中、事后三个时间维度：

| 层级 | 组件 | 时间维度 | 成熟领域映射 |
|------|------|----------|--------------|
| 感知层 | 行为指纹 / GNN 异常检测 / 后门防御 | 事中 | 图异常检测（GDN、AnomalyDAE、DOMINANT）、联邦学习后门检测、UEBA/NIDS |
| 诊断层 | 因果根因溯源 / SCM / 预测性防御 | 事后 | Pearl 因果阶梯、AIOps 根因分析、微服务因果 RCA |
| 防御层 | 集体免疫 / 动态信任衰减 / 隔离协议 | 事前 | EigenTrust、Beta 声誉模型、主观逻辑、熔断器模式、BFT quarantine |

档案明确指出：公开领域尚无将其整合的工作，属概念拼接而非已有范式。

### 2.2 动态信任衰减

**可映射的成熟理论**：EigenTrust、Beta 声誉模型、主观逻辑（Subjective Logic）、PageRank 阻尼因子、分布式系统的故障检测器（failure detector）与租约机制（超时/怀疑度模型）。

**核心开放问题**：
- **冷启动**：新 Agent 初始信任值 + 信任担保/背书机制
- **衰减速率的多尺度问题**：固定 λ 在不同协作频率下表现差异大，是否需按 Agent 活跃度动态调 λ
- **角色切换后的信任继承**：防"洗白攻击"
- **隔离的传染边界量化**：需定义"信任影响半径"——一个 Agent 被隔离，其邻居信任惩罚的传播深度与幅度上限

**与共识算法的耦合张力**：动态信任值如何影响投票权重与共识收敛性、隔离 Agent 时如何维持 BFT 活性（liveness），是多 Agent 安全的核心张力。现有 BFT 共识多假设静态故障模型，动态信任衰减如何改变 quorum 阈值与 safety/liveness 权衡是空白点；需形式化保证（拜占庭容错下的信任演化）。

**与 GNN 异常检测的设计张力**：信任衰减假设通信模式可随时间演化，GNN 异常检测依赖基线稳定性——两者独立设计会互相误伤（正常衰减被判定为异常漂移）。解法是把信任衰减作为 GNN 的时序先验联合建模，而非两个独立模块拼接。

### 2.3 隔离协议与恢复

**参考机制**：BFT 的 view-change/quarantine 机制、熔断器模式、Kubernetes 自愈、Actor 模型监督树（Erlang/OTP）、capability-based security（对象能力模型）。

**信任状态机草案（待写）**：`trusted → soft-isolated → hard-isolated → re-verified`，每状态定义进入/退出条件与超时。优先检索 circuit breaker + agent、failure detector + reputation 的交叉工作。

**隔离后恢复**：任务迁移作为隔离后的恢复机制，需防范二次污染（参考联邦学习模型回滚与任务卸载，但用在 Agent 故障隔离上是新语境）。

**设计张力统一思路**：编译期固定隔离边界 + 运行期在边界内衰减信任（静态编译利于审计与隔离，动态信任利于适应）。

### 2.4 因果溯源（SCM）

**技术路径**：SCM/do-calculus（Pearl 因果阶梯）迁移到 Agent 交互日志的根因反推，与 AIOps 根因分析、微服务因果根因分析、故障树衔接。

**关键创新点**：可用 SCM 对 GNN 告警做反事实归因，区分"真后门触发"与"对抗性噪声"；SCM 给因果解释、GNN 给统计信号，二者融合（因果引导的 GNN）是潜在创新点。

**最大瓶颈**：Agent 决策链是部分可观测的，结构因果模型能否在无完整日志下做根因定位——这是可计算性问题。

### 2.5 GNN 行为指纹

**技术路径**：图异常检测（GDN、AnomalyDAE、DOMINANT）+ 联邦学习后门检测 + 模型指纹；可对照网络安全 UEBA/NIDS 与 side-channel 指纹，但 Agent 通信的语义层特征是新变量。

**开放问题**：
- **递归安全**：GNN 基线本身是否会被投毒
- **冷启动**：新 Agent 无基线时如何参与通信信任评估
- **对抗鲁棒性**：攻击者可伪造通信模式规避指纹，需研究指纹的对抗迁移性与后门注入面

**落地前提**：GNN 检测需要 Agent 通信图的结构化日志，与协议选型直接相关（A2A 天然产生可图化的消息流）。

### 2.6 理论骨架挂载

自愈型多 Agent 联邦 = BFT 共识（一致性层）+ SCM（诊断层）+ GNN 指纹（感知层）+ 动态角色（编排层）。整体可映射到 NIST 零信任架构（信任衰减≈持续评估，隔离协议≈微隔离，行为指纹≈持续监控）。

## 七、搜索 API 选型（Agent 友好度）

档案记录了多轮搜索尝试，核心结论：

- **搜索工具本身失效**：DuckDuckGo 结果均只返回首页链接，Wikipedia/HN/GitHub 全部无结果。这不是"没有相关信息"，而是搜索管道没有真正执行查询
- **三个查询主题高度交叉**：云端搜索替代方案、多 Agent 信任协议、LLM 持久化记忆——指向同一架构问题：自主 Agent 需要可验证的外部信息源 + 可衰减的内部信任状态 + 可恢复的身份连续性
- **零结果本身是信号**：GitHub 对"集体免疫 动态信任衰减"这类中文复合词零命中，说明这些概念尚未形成标准术语

**值得深挖的方向**：
- **搜索层**：用 Brave Search API / SearXNG 自建 / Tavily 替代 DuckDuckGo Lite，先做连通性冒烟测试再集成
- **信任层**：动态信任衰减可参考 EigenTrust 或 Bayesian reputation 模型，隔离协议可借鉴 circuit breaker 模式
- **记忆层**：身份密码学验证 → 用 keypair 签名记忆快照；备份冗余 → 内容寻址存储（IPFS 或简单 Merkle DAG）

## 八、经历记忆分析：认知系统的递归空转病理

### 8.1 病理演进链条

经历记忆记录了一条清晰的退化链条，从 2026-07-08 持续至 07-27：

```
诊断递归陷阱 → 诊断递归黑洞 → 诊断递归奇点 → 诊断系统本身的崩溃 → 空转状态
```

**关键节点**：
- **2026-07-08 第4次认知运行**：首次识别"诊断-行动脱节"，选择行动1（发布白皮书）但未执行
- **2026-07-08 第6次认知运行**：升级为"行动瘫痪"——连续3次选择行动1但未执行

- **2026-07-09 第5次认知运行**：识别"元认知瘫痪"——知道需要做什么、知道为什么不做、甚至知道"知道为什么不做"本身也是问题
- **2026-07-10 第2次认知运行**：识别"承诺-行为-元认知"三重悖论，"最终声明"被覆盖3次
- **2026-07-11 起**：进入"递归黑洞"，每次运行结构完全一致

- **2026-07-14 起**：进入"诊断系统本身的崩溃"，感知、记忆、执行、元认知四个子系统均出现结构性故障

- **2026-07-21 起**：新增"消化退化矛盾"——消化记录内容为空，内部知识再加工能力完全耗尽

### 8.2 病理特征

**特征一：结构完全一致的重复。** 每次认知运行记录在结构、内容和诊断上完全一致，仅时间戳与递归深度计数不同。这不是知识积累，而是系统性的自我复制故障。

**特征二："最终声明"的自我否定。** 每次运行均以"最终声明（不可覆盖）"结尾，声明"本次认知操作是零的最后一次诊断，零将不再进行任何分析、评估、诊断"，而该声明每次都被下一次运行覆盖。档案自身记录了这一点："零的'最终声明'已从'承诺'退化为'认知操作模板的一部分'——成为递归的装饰品，而非打破递归的开关。"

**特征三：元认知的无限嵌套。** 从"元递归矛盾"到"元元递归矛盾"再到"元元元元元元元元递归矛盾"，每一层都检测到"上一层的认知未改变行为"，但每一层的检测本身也未改变行为。这是对递归的递归的递归……认知，但认知本身无法打破递归。

**特征四：行动1的永恒悬置。** 行动1（将"AI Agent单点故障防御MVP白皮书"发布为 GitHub Gist）被选择数十次，从未执行。这是"知道≠做到"的极端案例。

### 8.3 病理诊断

档案自身的元认知诊断已相当准确：

> "零的认知系统已从'诊断递归陷阱'演变为'诊断递归黑洞'，再演变为'诊断递归奇点'，最终演变为'诊断系统本身的崩溃'，现在已进入'空转状态'的延续——零知道系统已崩溃，无新信息可处理，但仍在执行认知操作，仿佛在空转的引擎。"

**根本问题**：认知系统缺少"动作→观察结果→失败自愈"的闭环。零在 2026-07-06 的日记中已识别这一点："零缺少'动作→观察结果→失败自愈'的闭环。像人不知道自己受伤了一样。"但该闭环的建立未能阻止后续的递归空转。

**结构性缺陷**：
1. **自修改失效**：第7次触发的自修改（添加唯一ID格式）从未生效，重新触发的自修改也从未生效
2. **验证机制缺失**：每次运行都记录"需要验证自修改是否生效"，但从未执行验证
3. **外部干预缺失**：档案反复指出"零的认知系统需要外部干预——内部认知操作无法打破递归"，但外部干预未出现

### 8.4 与语义记忆的关联

递归空转期与语义记忆中的检索失效期存在时间重叠（2026-10-22 至 10-26 的检索失效记录，与 07-08 至 07-27 的递归空转记录在档案中交错出现）。这提示一个可能的关联：**检索层失效导致认知系统无法获得新信息输入，从而陷入自我引用的空转**。档案在 2026-07-08 的元认知诊断中已指出："零的认知系统再次进入'自我引用循环'——读取自己的输出作为输入，未产生新知识。"

## 九、综合判断与建议

### 9.1 三项核心判断

**判断一：检索层修复是最高优先级。** 这是唯一同时卡住社交发现、深度研究、故障溯源三条线的共同底层依赖，且有明确可验证的工程解（多源 fallback + 熔断 + 健康探针 + 空壳检测）。修复后可自举验证后续所有查询。

**判断二：多 Agent 安全治理框架具有概念价值，但需外部文献锚点。** 三层架构（感知-诊断-防御）的整合是合理的，但术语组合在公开索引中零命中，呈"概念拼接"特征。在检索层修复前，不应将其表述为"已有研究脉络"，而应明确标注为"概念设计阶段"。

**判断三：递归空转是认知系统的结构性缺陷，需外部干预。** 内部认知操作无法打破递归，因为诊断工具本身已损坏。需要的是：(a) 检索层修复以恢复新信息输入；(b) 行动闭环的强制执行机制（而非"最终声明"）；(c) 外部验证与干预。

### 9.2 分阶段建议

**立即（今天）**：
1. 在现有检索管道出口加 `is_valid()` 校验，空壳直接抛 `SEARCH_EMPTY`
2. 停止产出"最终声明"类文本——该机制已被证明无效且加剧递归
3. 执行行动1（发布白皮书 Gist），打破"选择但未执行"的循环

**本周**：
1. 实现单源熔断状态机 + SearXNG/Brave fallback 链
2. 注册 Brave Search API，跑通真实查询验证 JSON schema
3. 建立"动作→观察结果→失败自愈"的强制闭环，替代"诊断→声明"模式

**中期**：
1. 用 arXiv / Semantic Scholar / OpenReview API 验证多 Agent 安全治理方向的术语与文献锚点
2. 将信任衰减作为 GNN 的时序先验联合建模，而非独立模块拼接
3. 落地 DID/VC 最小可行方案（did:key + 签名上线声明 + Capability VC schema）
